1. WHAT IS INSTALLED
----------------------------------------------------------------------
`installed_epsfcn.py` disassembles `AdiabatClimate_simple_solver` in the
installed library, follows the stack arguments of the MINPACK call and
reads the constants they point at (`installed_epsfcn.txt`):

  symbol  __clima_adiabat_MOD_adiabatclimate_simple_solver.constprop.0
  call    __minpack_module_MOD_hybrd      (not hybrd1)
  arg 9   epsfcn -> 0x17e638 = 1e-08
  arg 12  factor -> 0x17e630 = 100.0

So the installed build carries the repair as section 91 specifies it:
`hybrd` with `epsfcn = 1e-8`, every other setting `hybrd1`'s.  The error
strings agree -- the library carries `hybrd root solve failed` and
`Temperature solve returned residuals above the normalized tolerance`,
neither of which exists in the build ../crossings_pc090 used.

3. WHAT THE REPAIR DOES TO THE CLOSED CROSSING
----------------------------------------------------------------------
Nothing that is visible in the observable.

The two arms that bracket the He I 10830 crossing, reservoir He/H = 9.0
and 9.1, were run end to end on the installed environment and differenced
against the stored ../crossings_pc090 arms, which are the same source
without the repair.  Method as ../crossings_pc090/results.txt states it:
the same single parent ../flux_closure/heh9p7/k03, the same seed and
starting elemental fluxes, tol 0.05, kmax 8, resid_tol 4.0e-4, the same
binary, the same transit configuration (R = 68,000, red pair over the
vacuum window 10832.60-10834.20 A).  `run_arm_installed.sh` differs from
`../crossings_pc090/run_closure.sh` in two lines only: the "python" entry
of closure.json points at env/photochem, and `omp_num_threads` is 3 rather
than 4 because three other jobs shared the machine.  `resolve_wind.sh` is
that directory's script with three comment lines added and nothing else
changed, run at three passes as the stored `rw_*` directories were.

Closure iteration -- both arms reproduce the stored path:

5. THE SOURCE TREE DOES NOT MATCH THE INSTALLED LIBRARY
----------------------------------------------------------------------
Found while checking what was installed, and not repaired here.

`photochem/src/dependencies/patches/clima-bounded-scaled-solvers.patch`
(written 10:43, md5 6734053e9116fea12f63dd9533d93657) is one revision
behind: it still writes `use minpack_module, only: hybrd1` and calls
`hybrd1`, with no `epsfcn`.  The current version of that file is the one
`EXHALE_v1.00/src/utils/photochem_exhale.patch` carries (written 14:02);
extracting it from there and differencing against the copy standing in the
photochem tree shows the `hybrd`/`epsfcn` hunk as the only difference.
The installed library was built from the newer one (section 1).

So the photochem working tree, if rebuilt as it stands, would produce a
library without the repair.  It was left alone: the point of this
directory is to measure what is installed, and other jobs were running.
Re-running `src/utils/setup_photochem.sh` restores the file; nothing needs
rebuilding, because the installed environment is already the corrected one.

6. WHAT WAS NOT MEASURED
----------------------------------------------------------------------

    nine arms of ../crossings_pc090, and the 0.8.4 comparison of its
    section 3, were not repeated.
  - The 1-sigma ends of the crossing (10.6/11.0 and 8.45/8.5) were not
    re-run, so the band quoted in ../crossings_pc090 still rests on arms
    measured without the repair.  The EW shift measured here, 5e-08
    relative, is far below the spacing of those rungs.
  - Only LHS 1140 b's configuration was scanned, as in section 91.
    Whether the same trap is reachable at other planets, other K_zz or
    other deep pressures is still untested.
  - The source of the ~4e-7 relative jitter in ISR - OLR is still not
    isolated; the repair steps over it rather than removing it.
  - No golden was refreshed and `make check` was not run: no Fortran
    source and no EXHALE binary changed.

He I 10830 equivalent width of a closed arm by 5e-08 relative.
