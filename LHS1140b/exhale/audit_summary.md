## Runtime-checked (`-fcheck`) run of He/H = 1000

Kept by hand; `audit_checks.py` regenerates only the sections above.

Case `heh1000_fcheck/` is `heh1000/input.inp` with the planet name changed,
its IC being the converged `heh1000` solution, run with the same JFNK
invocation (`EXHALE_PTC=1 EXHALE_PTC_JFNK=1 EXHALE_PTC_DTAU0=1.0`).

**Bounds and memory checks** (`-O1 -fopenmp -g -fcheck=bounds,do,mem`,
the flag set of `backup/regression/run_fcheck.sh`): the solve completes,
`done info=0 ||R|| = 7.929E-04` after 2 iterations, and no bounds, `do`, or
memory check fires (`run.log`).

**Floating-point exceptions.** That same run ends with the gfortran summary
`IEEE_INVALID_FLAG IEEE_UNDERFLOW_FLAG IEEE_DENORMAL` — notably *without*
`IEEE_DIVIDE_BY_ZERO`. Rebuilding with `-ffpe-trap=invalid,zero,overflow -g
-fbacktrace` added and re-running (`run_fpetrap.log`) locates the invalid
operation: SIGFPE at

```
UW_conversions.f90:58   W_out(2,:) = U_in(2,:)/U_in(1,:)
  called from Apply_BC.f90:18       (call U_to_W(u,W))
  called from steady_newton.f90:233 (call Apply_BC(u))
  called from steady_newton.f90:844 (the first eval_residual of the JFNK solve)
```

`U_to_W` converts the whole array, ghost cells included, and at that point
the ghost cells of `u` are still zero, so the velocity of each ghost is
`0/0`. The absence of `IEEE_DIVIDE_BY_ZERO` in the untrapped run's summary is
consistent with a zero numerator as well as a zero denominator. The comment
at `steady_newton.f90:228-229` states exactly this situation ("the ghosts are
still zero at this point and U_to_W would divide by them") for the
`get_species_densities` call immediately above; the `Apply_BC` call on the
next line goes through `U_to_W` anyway. `Apply_BC` then overwrites the ghosts
through `Apply_BC_W` and converts back, so the NaN is discarded rather than
propagated — which is why the untrapped run converges normally and every
output column is finite.

Nothing in this path depends on He/H, so it is expected in any JFNK run.

**Fixed the same day** (`docs/Update_EXHALE.md` sec. 66). Every site that
converted a state whose ghosts were not filled now converts the interior
cells only, through one routine, `U_to_W_interior` in `UW_conversions.f90`:
`Apply_BC` (the site above), and the two line-search trial conversions in
`steady_newton.f90` (`call U_to_W(utry, Wtry)` at the hybrid and JFNK
searches), which unpack only the interior of the trial vector and then test
`Wtry(1,1:N)`, `Wtry(3,1:N)` for positivity -- the second `0/0` the trap
exposed once the first was gone. The ghost primitives were never read at
any of the three sites, so the change cannot alter a result.

With both fixes, the trapping binary (`-ffpe-trap=invalid,zero,overflow`)
runs the same JFNK to completion: `done info=0 ||R|| = 7.929E-04`
(`run_fpetrap_fixed2.log`), the same residual as the untrapped run, and the
exit summary lists no signalling exception. The H-rich counterpart
(`solar_gj699`, He/H = 0.083, run from its converged state in a scratch
directory) also completes under the trap, `info=0 ||R|| = 6.433E-04`. The
steady-solver path is therefore free of invalid operations on both ends of
the composition axis. `run_fpetrap_fixed.log` is the intermediate run that
still trapped at the line-search site (`steady_newton.f90:943`).

`heh1000_fcheck/output/` now holds the solution written by the fixed
trapping run; `run.log` (bounds checks, pre-fix), `run_fpetrap.log` (first
trap, pre-fix), `run_fpetrap_fixed.log` (second trap, after the `Apply_BC`
fix alone) and `run_fpetrap_fixed2.log` (clean, both fixes) are the records.
