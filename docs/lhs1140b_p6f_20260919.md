# The transit spectrum of a solved state (2026-09-19)

PLAN_20260919_rev1 item P6f, replacing the withdrawn text of that item and
following section 9.3 of `PLAN_20260919_review.md`. Every number below is
MEASURED on 2026-09-19 with `MPLBACKEND=Agg python3 EXHALE_transit.py` on
scratch copies of two regression cases, unless it is marked READ. No wind
solve was run and no `EXHALE.x` was executed.

## 1. Verdict

The solution selection works, and it is now the only way a stationary run is
read. On a marching case that carries both states the choice moves the He I
10830 peak depth by 0.6 per cent of itself, the H-alpha peak by 1.3 per cent
and the H-beta peak by 3.5 per cent, and leaves the Ly-alpha peak at the
saturated ceiling; the metastable radial column is 12 per cent LARGER in the
solved state while its depth is slightly SMALLER, because the advection
correction moves the metastable outward rather than adding to it. The
certified stationary state `backup/regression/iontrans_metals`, which has no
`_adv` products at all, now produces a full spectrum.

Three defects of the tool were found and fixed:

1. the default selection on a run with no `_adv` products died in
   `numpy.loadtxt` with a bare `FileNotFoundError` naming one file, saying
   nothing about which state was asked for or what to do;
2. a saved curve named the files it read by path only, and a run directory is
   written again by the next run, so the curve was not traceable to the
   numbers behind it; the state's own boundary model and reservoir never
   reached the curve at all;
3. the O I ground-term level populations were read from `OI_levels_adv.txt`
   whichever state was selected, so a solution-state O I 1302 line would have
   been built from the post-processed level populations. On
   `iontrans_metals` that file does not exist and the line was skipped
   instead; with the selection honored the line is computed, peak depth
   0.2441 per cent.

## 2. What the two selections mean

They are two answers for one column, not two formats of one answer.

The `_adv` pair is a POST-PROCESS of a marching state. It applies a steady
advective correction cell by cell, first-order upwind at the bulk velocity,
with no eddy term and no element drift, and refuses that correction in a cell
where an assumption of the steady equations fails (READ, the writer's own
schema and `read_adv_validity`). It is an independent discretization of the
same column, and no equation of the run was solved for it.

The solved pair is the state the solver produced and the certification
judged: the state whose residuals were measured against a tolerance. Where
the ionization stages are transported, its composition is the partition the
stage transport itself produced, so applying the advective correction on top
of it would be a SECOND and different transport approximation of the same
stages laid over the one that was solved.

Therefore a stationary route writes no `_adv` products, none are to be
manufactured for one, and the default selection refuses by name rather than
reading the other state. The two files of a selection are read together: the
temperature of one state with the composition of the other solves neither set
of equations.

| quantity | largest relative | at | solution | adv |

and the integrated quantities move much less than the pointwise maxima: the
radial H I column of the solved state is 0.99755 of the corrected one, and its
metastable helium column is 1.11871 of it. The metastable column is 12 per
cent larger in the solved state and its line is nonetheless 0.6 per cent
shallower, because the correction shifts that column outward: the
column-weighted mean radius of n(He 2^3S) is 1.2941 R_p in the solved state
and 1.3112 R_p in the corrected one, and a disk-averaged depth at a saturated
line center is set by how far out the absorbing shell reaches, not by how much
is in it. The Ly-alpha peak does not move at all because it is at the
saturated ceiling in both states. H-beta, the weakest of the hydrogen lines
here, moves most, since it is the one still on the linear part of the curve of
growth where the column and the n=2 population enter directly.

Mean temperature over 1.0 to 1.6 R_p is 6204.4 K in the solved state and
6079.8 K in the corrected one; the metal lines, which are optically thin
enough to follow the column and the Doppler width, all move upward by a few
tenths of a per cent with it.

The `certified=T cert_reason=certified_in_wind` of the `coupling` line is the
run state's certification, and the header says so beside the `adv_input`
block, which states for this file that the row validity is UNKNOWN: a solved

A run directory is written again by the next run, so the digest, not the
path, is what ties a curve to the numbers it stands on. Reading a resolved
generation directory or a staged immutable copy is preferred over a moving
`output/`; both states here were read from staged copies.

## 5. Changes

`exhale_transit_lib.py`

- `transit_state_files(path, selection, require=True)`: the pair a selection
  names must be on disk, and a missing one is refused by `FileNotFoundError`
  naming every missing file, saying that a stationary solve writes no `_adv`
  products, and naming the other selection. The other state is never read in
  its place. `require=False` is for a caller that is only asking where the
  other state would be.
- `file_identity(path)`: path, md5 and size, or `absent`.
- `state_provenance_statements(path)` and `STATE_PROVENANCE_KEYS`: the
  `provenance`, `source`, `boundary_model`, `boundary_reservoir`, `coupling`
  and `option_change` statements of a profile's own header, copied out
  unchanged.
- `transit_state_oi_levels(path, selection)`: the O I ground-term level file
  of the selected state.
- `transit_metadata_block`: emits `state_file_identity` for each file read and
  `state_<key>` for each statement the state makes about itself.

`EXHALE_transit.py`

- the selection is resolved inside a guard, so a refusal prints its reason and
  exits instead of unwinding a traceback out of `numpy.loadtxt`;
- the state record carries the identities and the provenance, both printed at
  startup and written into every saved curve;
- the O I level file follows the selection;
- the comment block at the head of the file states what the two selections
  mean, as section 2 above.

The numerical columns of the default selection are unchanged: on `wasp_full`
with the default selection, all ten products (`tpm_He10830`, `_metrics`,
`Lya`, `Halpha`, `Hbeta`, `MgII`, `CaII`, `NaI`, `OI`, `OI_band_depths`) are
identical outside the comment header to those of the same run before the
change.
