## D1. The default base cell width and the input key

### Facts, READ

`parameters.f90` line 143 and `input_read.f90` line 451 assign
`dr_base = 2.0e-4`, a default-real literal, stored as
`1.9999999494757503e-4`; the key is read list-directed into a `real*8`, so
`2.0e-4` in the key gives the exact double, 2.53e-8 relative above the
default (review arithmetic check). The comment above the literal states
the choice as deliberate (bitwise reproduction of runs made before the key
existed) and states the trap (the spelled-out default does not reproduce
it). L35 MEASURED cell centers differing by up to 6.58e-9 relative on the
catalog grid between the two; `load_IC.f90` lines 2221 to 2244 refuse a
restart whose centers differ by more than 1e-10. `dr_base` enters the
`Mixed` branch of `define_grid` only (lines 31 to 34).

### The defect

Two inputs any reader would call identical build two grids whose states
refuse to load into each other. The refusal itself is right: loading a
state onto a grid it was not written on is interpolation, and the 1e-10
check must stay. The defect is the contract, not the physics (2.5e-8 in one
cell width).

### Corrections to the first text

- "Every grid moves": only Mixed grids built from the default move. Grids
  whose width is stated in the key, and other grid types, do not.
- An archived state does not have to be MAPPED because the default
  changes: it keeps its grid by stating its resolved width and base-cell
  count explicitly. Mapping is for moving a state to a different grid on
  purpose, and a mapped state is a seed, not a certified solution of the
  new operator.
- The forecast "movement at the level L30b measured for a 4e-13 seed" is
  withdrawn: a grid change is not a rounding perturbation and L30b's
  numbers do not predict its response.
- 17 digits are not printed today: `put_r` uses `ES23.15E3` (16
  significant digits). The disclosure goes into `write_resolved_config`
  (machine-readable) with a round-trip serializer: NOT `ES24.17E3`, which
  the second review showed overflows to asterisks for a negative value and
  carries 18 significant digits; a sufficiently wide explicit format
  (`ES26.17E3` printed the negative value) or a defined shortest-exact
  decimal, tested on both signs, zero, representative exponents and the
  parse back to the same binary64 value.
- "Default or key" needs a provenance flag set by the reader; value
  equality cannot say where a value came from. The duplicated literal in
  `input_read.f90` is replaced by one named default in `parameters.f90`.

### Steps

D1a (now, no numerical change): one named default `dr_base_default`; a
logical `dr_base_from_key` set by the reader; `write_resolved_config`
records grid type, width (round-trip precision), base-cell count, cell

compared directly); the key stating `2.0e-4` differs, and the row reports

D1b (on the user's approval): a global default cannot tell an old input
from a new one by its age, so "new configurations only" is true only after

## D2. The base boundary at zero and reversed flow

### Facts, READ

L26 wrote the window's say as `s_wind = A(M_wind) C(d_window)`;
`characteristic_branch_weight(x)` is the cubic `0.5 - 0.75 x + 0.25 x^3`
(`base_boundary.f90` lines 489 to 505), 1/2 at zero. L35 MEASURED on the
fiducial with momentum and kinetic energy removed: the window flux exactly
zero, the interior velocity zero, `w_rev = 1/2`, the base density the
average of the reservoir and interior isentropes, the local candidate's
face density 3.79 per cent above the remote closure's (the remote density
as denominator; the remote closure's deficit relative to the reservoir is
a different percentage); the flux-inferred local face Mach number on that
fixture is NOT zero (6.05e-6, L35 section 4.3); the production closure's
base mass flux there 1.2751e-5, the local candidate's 1.3791e-5 (L35 memo
line 679). Three velocities must be named apart: the interior cell
velocity, the characteristic boundary-state velocity `v_b`, and a velocity
inferred from the numerical Riemann flux; L35's "face Mach" is the third.

### What the first text got wrong

It argued that at rest no characteristic leaves the domain, so the face
must be the reservoir. At rest the characteristic speeds are `-c_s, 0,
+c_s`: one acoustic characteristic leaves, one enters, and the contact is
stationary. The code's own outgoing relation (`C-`, line 37) gives
`v_b = v_i + (p_b - p_i)/(rho_i c_i)`, so zero interior velocity does not
make the face velocity zero; a pressure mismatch launches a legitimate
acoustic response, which is what the fixture's nonzero base flux is. And
the fixture is not a hydrostatic equilibrium: it is a wind with its
momentum deleted. So the measurement shows that the blend's value at zero
is a model choice with no stated physics behind it; it does not show that
the reservoir density is the right value, and the "+8.2 per cent" of the
local candidate is not a restoration of equilibrium.

Also withdrawn: "a C1 factor that is 0 at exactly zero flow and 1 wherever
either discriminant is resolved, leaving every flowing state byte-identical".
A continuous weight equal to the old one at every nonzero argument is 1/2
at zero; a weight that vanishes at zero changes a neighborhood of zero,
whose width is a parameter that must be justified (review arithmetic
check: the difference quotient of a change confined to zero diverges).
Byte identity can be measured on chosen saturated states; it cannot be
promised for all flowing states.

### The item

D2a, a decision the user makes on a stated model, presented as concrete
alternatives with the incoming-characteristic data each requires, not as an
abstract question:
- (A) the reservoir owns the contact at rest: the entering acoustic
  characteristic carries `p_res`, the contact carries the reservoir's
  entropy and composition whenever it does not move outward; at rest the
  face is the reservoir state and the outgoing acoustic relation fixes
  `v_b` from the pressure mismatch;
- (B) the interior owns the contact at rest: the entering characteristic
  carries `p_res`, the contact keeps the interior's entropy and composition
  unless material actually enters; at rest the face density is the
  interior isentrope at `p_res`;
- (C) a stated thermal contact model: a conductive or relaxation closure
  between the two entropies with a named length or time scale, of which the
  present smoothstep midpoint is one unnamed instance;
each stated with which quantities `base.inp` prescribes and at which
reference radius (`p_base`, `T_base`, `q_H2_base`, the element reservoirs,
the match level), how the stationary pressure-balanced contact with two
entropies is treated, and how the boundary passes through weak inflow, weak
outflow and reversal without imposing outgoing information.

D2b, after that: implement the stated model in `base_boundary.f90` with
the blend width, if one remains, named and justified; tests on a
manufactured DISCRETE hydrostatic state consistent with the molecular
equation of state and the reservoir (face velocity, mass flux, momentum
and energy balance), a stationary pressure-balanced contact with differing
entropy and composition with its expected behavior stated in advance,

the temperature stops moving. The comment's claim that a temperature
change below the reaction tolerance cannot move the composition beyond it

bounded against the returned one. Separately, `ieq_res_tol` is a reaction

every species after another nonlinear sweep without conditioning
information. So two outcomes remain open: production exits early against
its own promise (repair the stopping rule), or the test assumes a stronger
bound than the residual contract gives (revise and rename the assertion
with a defensible norm and add a direct returned-state residual check).

## D6. Helium held in HeH+ is not reserved from the helium ion-stage simplex

  measures: a snapshot written after the update cannot inherit that
  certificate.
- `trust_pass` starts from `carrier_trust` (near line 6756) and only
  shrinks; a restart from the hydro/species pair resets it and every other
  solver control, which is one reason the continuation's trajectory
  differs.
- `pick_seed.py::certified` trusts a `REPRODUCE.md` certification line
  before the log, unbound to the data files' hashes or generation;
  `run_campaign.sh` captures `run_case.sh` through `tail -n 1` without
  `pipefail`, so a failed case yields exit 0 and a last line that is the
  re-measurement sentence; `run_case.sh` edits `input.inp` in place for the
  evaluate pass and restores it after the binary returns, so a killed
  runner leaves the solve input transformed.

### The defects

A run directory must state one solve: its seed, its trajectory, its best
state, its ending. Today the runner can publish a worse state over a
better one with no record; a directory can hold products and seeds of
different generations; a reader can combine them; a certificate can be
attached to a state it did not judge; and a campaign can report success
after a failure. None is a physics defect; each misleads the catalog and
every seed taken from it.

### The item (its shape agreed before implementation, as D5b's is)

1. **Preservation now, without a new format**: the runner never deletes or
   overwrites a completed generation; the continuation writes into its own
   directory and the case directory keeps the first solve's output beside
   it, with the ending reason of each recorded. No claim of "best" yet.
2. **Continuation policy**: the classification (composition-only budget
   exhaustion, a supported hydrodynamic ending, a nonfinite or inadmissible
   state, a missing verdict) precedes the decision, and the continuation is
   taken only for the endings it addresses; an aggregate nonzero `info` is
   not a reason. Stated in `run_case.sh` where it fires.
3. **Generations**: a completed generation is a directory holding both
   data files and a manifest (run and attempt identifier, iteration
   identity, source, binary and configuration identifiers, file hashes,
   dimensions, completion status, the certificate's state identifier); it
   is published by one atomic pointer update on the same filesystem after
   the files are closed and validated, the previous completed generation
   kept until the new one is usable. Readers (`load_IC`, the mapper,
   `pick_seed`, `status`, `write_reproduce`) resolve the pointer once and
   read both components from that generation; an incomplete generation is
   refused or a complete checkpoint generation is chosen explicitly, never
   one component from each. Since the workspace is on NFS, the guarantee
   implemented (process interruption against server failure) is stated and
   tested on that filesystem; two separate renames are not a transaction.
4. **One state identity**: the certificate names the state it judged and
   the snapshot carries the same identifier; a snapshot of the updated
   state is either the state that was evaluated or is evaluated before its
   score is attached. Ranking for reporting (admissibility and complete
   evaluability first, then certification, then a named normalized
   distance, with the full vector of row measures, scales, gates and
   provenance kept beside it) never resets the solver trajectory, and
   latest, best and certified generations stay distinct.
5. **Warm restart against exact continuation**: a restart from the
   physical pair rebuilds derived quantities and restarts the solver
   controls under a documented policy (warm restart); exact algorithmic
   continuation would also carry the trust bound, relaxation parameters,
   progress history, reconstruction state and counters and is verified
   against an uninterrupted control. The contract says which it is;
   neither is physical time evolution.
6. **The checkpoint writer**: a focused writer whose input is one
   synchronized snapshot and whose execution does not change subsequent
   solver behavior, not the full `write_output` path at every pass.
7. **The evaluate pass** runs in a separate directory or configuration so
   a killed runner never leaves the solve input transformed; the campaign
   aggregates a machine-readable non-success status while keeping every
   case's outcome.
8. The movement bound's recovery on a progressing pass is a solver-control
   change under the rule that closed the stage-2 program: not made; the
   bounded experiment (the bound held at 1e-2 for ten passes on the stopped
   `wellmixed/HeH0.083` state, L33's design) is the user's to open.

Tests: the four ending classes handled separately; interruption before any
output, during the hydro write, between the two component writes, during
manifest publication and during post-processing, after each of which a
reader obtains the previous or the new completed generation and never a
mixed pair; an old certificate with new files, identical pass numbers from
different attempts and a truncated file refused; the ranking certificate
belonging to the exact stored state; one failed campaign case producing a
non-success aggregate; checkpoint output not changing the next numerical
update, and, if exact continuation is claimed, interrupted-and-resumed
against uninterrupted histories.

## D9. The pass budget of a transported-ionization solve, seed compatibility and the reference refresh

### Facts, READ from L36e (MEASURED there) and the second review's arithmetic

On the certified atomic fiducial with `Ionization transport: True` the
worst gated species row and its binding cell went 3.51e-2 at cell 217
(pass 1), 2.05e-2 at 416 (2), 1.91e-2 at 444 (10), 1.80e-2 at 475 (20),
1.76e-2 at 491 (25); the maximum then fell to 8.68e-6 and the state was
ACCEPTED and CERTIFIED at pass 56. The binding cell is an `argmax` of a
normalized residual and can jump between cells and species (217 to 416 in
one pass); (491 - 217)/24 is 11.4 cells a pass and (491 - 416)/23 is 3.3;
outer passes are not time steps and the grid is nonuniform. The four
key-on regression cases are stale against the 2026-09-17 goldens
(`hp_front` 1.6e-1 in the helium columns, `hp_zero_seed` 3.9e-3,
`hp_trace_seed` 3.3e-3, `carrier_model_a_newton` 1.2e-4).
`pick_seed.py`'s `Physics.matches` returns true for two inputs differing
only in the ionization-transport key.

### What rev1 got wrong

It turned one recorded history into a rule ("about 3.3 cells a pass, at
least 40 passes before any gated row can begin to fall"): the maximum fell
from pass 1, the speed depends on which difference is taken, and a moving
argmax is not a measured front. The pass-56 acceptance is evidence for that
configuration, seed, algorithm and tolerances, not a lower bound for every
transported run. The front reading stays an interpretation until the
stage-fraction profiles are checked.

### The item

1. Budgets are measured, not derived: for the fiducial a bounded repeat
   with the recorded allowance (the 90-pass ceiling L36e used) as an
   empirical test of reproducibility; for other configurations a stated
   pass and wall-time ceiling with progress evidence and an explicitly
   authorized extension. A run stopped at its ceiling with rows above
   tolerance is UNCERTIFIED and INCOMPLETE, recorded with the residual
   profile, the binding species and radius, the scales, the admissibility
   and the solver-control history; it is never relabeled a solution because
   a front is suspected. A small declared matrix (seeds, resolutions,
   chemical and transport regimes) establishes which configurations need
   larger budgets; no catalog campaign is needed for that.
2. Seed selection puts compatibility before distance in every tier of
   `pick_seed.py` (reservoir inventory, available species, molecular
   chemistry, diffusion model, boundary and radiation configuration, the
   permitted conversion, the ionization-transport key), reads the state
   generation's resolved options (D8) and not only the directory's input,
   treats a local-equilibrium seed for a transported run as an explicit
   model-option transition with the restart permission it needs, and never
   transfers a certificate from the source problem to the target.
3. The reference refresh is acceptance work: the four key-on differences
   are kept as observations; the affected references are refreshed ONCE
   after D6, D7a and any boundary or closure correction that changes the
   correct result have passed their independent tests, with provenance and
   the measured differences, and unchanged paths are not regenerated. A
   larger budget and a new baseline do not repair a missing term, a wrong
   sign or a stale state evaluation.
