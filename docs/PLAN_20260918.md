## D1. The default base cell width, and the input key that cannot reproduce it

### The facts, READ

- `src/modules/init/parameters.f90` line 143: `real*8 :: dr_base = 2.0e-4`.
  The literal is DEFAULT-REAL (single precision), so the stored value is
  the single-precision neighbor of 2e-4, `1.9999999494757503e-4`, 2.5e-8
  relative below it.
- The comment above it (lines 134 to 142) says this is deliberate: the
  value is what the former hardcoded local in `define_grid.f90` was, and
  writing `2.0d-4` "moves every base cell by that amount and changes the
  last few digits of a converged solution", so the literal is kept "so that
  an input.inp without the key reproduces earlier runs bit-for-bit". The
  same comment states the consequence: spelling the default out in
  `input.inp` (`Base grid [dr,cells]: 2.0e-4 50`) does NOT reproduce it,
  because the list-directed read into a `real*8` gives the exact double.
  `input_read.f90` lines 451 and 452 repeat the literal with "default-real
  literal on purpose".
- L35 MEASURED the consequence on the catalog grid: stating the default
  explicitly gives cell centers that differ from the omitted-key grid by up
  to 6.58e-9 relative; the exact grid is reproduced only by writing the
  17-digit single-precision value (`0.00019999999494757503`).
- `load_IC.f90` line 2244 refuses a restart whose cell centers differ from
  the run's by more than `1.0d-10` relative (`restart_density_rounding_tol`
  at line 91 is the density tolerance; the grid check is the 1e-10 at line
  2221 to 2244). A state written on the omitted-key grid therefore does not
  load into a run that states the key with the rounded value, and the other
  way round.

### Why it is a defect even though it was deliberate

The choice bought bitwise reproduction of runs made before the key existed.
It costs a property the input contract is supposed to have: an input file
that states every key reproduces the run made with the defaults. Today two
inputs that any reader would call identical (`Base grid [dr,cells]:` absent,
and `Base grid [dr,cells]: 2.0e-4 50`) build two grids whose states refuse
to load into each other. Every catalog `input.inp`, every `REPRODUCE.md`
and every mapped seed inherits the trap, and L35 had to carry a 17-digit
literal into its inputs to run a matched comparison. The physics is
untouched either way (2.5e-8 in one cell width), so this is a contract
defect, not a physics one.

### Options

| option | what changes | consequence |
|---|---|---|
| (a) `2.0d-4`, the exact double, as the default | one literal in `parameters.f90`, one in `input_read.f90`, the comment rewritten | every grid built without the key moves by 6.6e-9 relative; every archived state (the 95 catalog cases, the `.L*` states, the 17 goldens) no longer loads without mapping through `map_state_to_grid.py`; the goldens are refreshed once (movement at the level L30b measured for a 4e-13 seed, i.e. rounding on the mechanical cases and up to 1e-4 on the two molecular snapshots with the root ladder, plus whatever `oxygen_chemistry` does, which is order unity by construction, item L30c) |
| (b) keep the literal, make the KEY reproduce the default | `input_read.f90` reads the key and, when the value read equals the exact double 2e-4, snaps it to the stored default; the setup report echoes the 17-digit value actually used | no grid moves, nothing needs mapping; the contract "stated key = omitted key" holds for this one value; the snap is a special case that has to be documented where it is, and a user who wants the exact double 2e-4 cannot ask for it |
| (c) keep the literal, document the 17-digit value as THE default and echo it | the comment, `docs/input_schema.md`, `write_setup_report.f90`; `REPRODUCE.md` writes the key with the 17 digits | no grid moves; the trap remains for a hand-written input that states `2.0e-4`, but the setup report shows the difference at startup and the reproduce files carry the exact value |
| (d) defer to the next full catalog re-solve | nothing now; (a) then | the trap stays until then |

### Recommendation

(a), at the start of the next catalog re-solve and not before, with (c) done
now. Reasons: (b) writes a special case into the reader for one number,
which is the kind of rule the next person cannot see; (c) removes the
surprise immediately at no cost; (a) is the only option under which the
input contract holds without a footnote, and its whole cost is one mapping
pass and one golden refresh, both of which the catalog re-solve pays
anyway. Until (a) lands, the L34 re-run, the L35 study and every seed
mapping continue on the omitted-key grid, which they already do.

### Steps of (c) now, (a) later

(c), now, no numerical change, one worker:
1. `write_setup_report.f90` echoes `dr_base` with 17 significant digits and
   says whether it came from the key or from the default.
2. `docs/input_schema.md`'s `Base grid [dr,cells]` row states the stored
   default to 17 digits and that `2.0e-4` in the key is a different grid.
3. `LHS1140b/models/write_reproduce.py` writes the key with the value the
   setup report echoed, never with a rounded spelling.
4. Test: a row in `src/tests/grid_and_gates/` that builds the grid with the
   key absent and with the key stating the echoed 17-digit value and asserts
   the radius columns identical to the bit; and a row that states `2.0e-4`
   and asserts the difference is what L35 measured (6.58e-9 relative
   maximum), so the trap is measured and not just described.

(a), at the next full re-solve, one worker, sequenced first in that series:
1. `parameters.f90` and `input_read.f90`: `2.0d-4`; the comment rewritten to
   state the contract (stated key reproduces omitted key) and the date the
   default moved.
2. Map every seed the re-solve will load (`map_state_to_grid.py --ic`,
   which already writes `certified=F cert_reason=mapped_seed`); the L34
   recipe does this for every case anyway.
3. Regression: run the matrix at `REGRESSION_REL_TOL=0` on the control and
   the measured build, report the movement case by case, refresh the
   goldens once with the previous set kept as `golden_D1_<date>/`.
4. Tests: the two rows of (c) with the reference now the exact double.

### What changes for the user

Under (c): nothing in any run; the setup report prints one more line and
`REPRODUCE.md` carries a longer number. Under (a): an `input.inp` without
the key builds a grid 6.6e-9 different from every state written before
that date; such a state must be mapped to load.

## D2. The base boundary on a column at rest

### The facts, READ

- L26 (`docs/lhs1140b_stationary_L26_20260916.md`) repaired a discontinuity
  of the base face density at a zero wind-window flux by writing the
  window's say as `s_wind = A(M_wind) C(d_window)`, `A` a cubic smoothstep
  in the window Mach number that vanishes at zero flux.
- `base_boundary.f90`: `characteristic_branch_weight(x)` (lines 489 to 505)
  is the cubic `0.5 - 0.75 x + 0.25 x^3`, 1/2 at `x = 0`; the handover
  comment (lines 700 to 720) says the weight is read as a function of
  `|M_wind|/blend`, "0 at 0, 1/2 at the blend width, 1 at twice it".
- L35 step 2 MEASURED, with the production face flux on `.L26/fid_resolve`
  brought to rest (`v = 0` everywhere): the window carries exactly zero
  flux, `A` vanishes, the first cell's face Mach number is also exactly
  zero, and the branch weight `w_rev` returns 1/2, so the base density
  becomes the average of the reservoir isentrope and the interior
  isentrope. On the fiducial the two differ by 7.3 per cent, so the
  boundary states a face density 3.79 per cent below the reservoir on a
  state where nothing flows (ghost cells 3.86 and 4.00 per cent). On the
  `hydrostatic_column` fixture the same 1/2 costs 3.07e-7, which is why the
  suites never saw it. On every FLOWING state tested (the two certified
  states, weak inflow, reversed flow, a remote-window perturbation) the
  local characteristic closure and the remote-window closure install a
  bit-identical ghost.

### Why it is a defect

The boundary's stated physics is a reservoir at `p_base`, `T_base` below the
domain. A column at rest is the one state in which the boundary's answer is
known without any solver: the base face must carry the reservoir's
thermodynamic state, and nothing else, because no characteristic leaves the
domain to say otherwise. A weight of 1/2 there is not a physical statement;
it is the midpoint of a smoothstep evaluated at the one argument where the
two branches it interpolates between have nothing to say. That no current
run sits at rest does not make the definition right: the hydrostatic
initial conditions, the well-balanced tests and any future static
equilibrium test all pass through it, and a boundary whose zero-flow limit
is 3.8 per cent off the reservoir cannot be the boundary of a
well-balanced scheme.

### Options

| option | what changes | consequence |
|---|---|---|
| (i) state the zero-flow limit as the reservoir | where the face Mach number and the window flux are both zero, the reversal weight is 0 (the entering characteristic carries the reservoir); implemented as the limit of the same smoothstep, not a threshold: the argument is scaled so that `x -> +inf` (weight 0) as both discriminants vanish, or the weight is multiplied by a factor that is 0 at exactly zero flux and 1 where either discriminant is resolved | the fiducial at rest gets the reservoir density; flowing states are untouched if the factor is 1 wherever `|M_wind|` or `|M_face|` exceeds the blend width (L35: on every flowing state tested both closures already saturate there) |
| (ii) leave the 1/2 and document it | the comment at the handover states the limit and its 3.8 per cent | the defect stays, named |
| (iii) replace the remote closure by the local characteristic closure everywhere | a larger change L35 explicitly did not recommend | not justified: L35 measured the two closures bit-identical on every flowing state, and the remote closure's nonlocality moves the face by 3.8e-5 under a 1.5x domain extension |

### Recommendation

(i), as a bounded item with a byte-identity control on every flowing
state. It changes the boundary only at the one point where its present
value is not a physical statement.

### Steps and tests

1. In `base_boundary.f90`, write the zero-flow limit once, at the place the
   weight is formed, with the physics stated: the entering characteristic
   carries the reservoir datum, so at zero flow the face IS the reservoir
   state. Form it as a C1 factor of the existing smoothstep argument (no
   `if` on a threshold; the L26 repair exists because a threshold there
   stepped the residual).
2. Tests in `src/tests/grid_and_gates/` (the L35 probe
   `base_closure_candidates_probe.f90` is the starting point; register it):
   the fiducial at rest gives the reservoir density to 1e-12 (RED today at
   3.79e-2); the `hydrostatic_column` fixture at rest likewise (RED at
   3.07e-7); the six flowing states of L35 give a ghost bit-identical to the
   entry text's (control rows).
3. Regression: `wasp_full`, `mol_base_handoff`, `lower_profile`,
   `hydrostatic_column` byte-identical on the data lines (every one of them
   flows; if `hydrostatic_column` is not byte-identical, the reason is that
   its first cell carries an inflow of 8.09e+4 cm/s, READ from L35, and
   that must be stated rather than absorbed).
4. The catalog states: the evaluate route on `.L26/fid_resolve` and one
   molecular state, before and after, byte-identical certification blocks.
5. Memo `docs/lhs1140b_stationary_D2_<date>.md`; the L26 memo's design
   section gets a head note pointing to it.

### What changes for the user

Nothing on any flowing state. A static test or a hydrostatic start reads
the reservoir density at the base instead of a value 3.8 per cent below
it.

## D3. The balance row of a fast ionization stage

### The facts, READ from the L36c and L36d reports and memos

- With `Ionization transport: True`, the fractions x(H II) per hydrogen
  nucleus and x(He II), x(He III) per helium nucleus are transported rows of
  the transport-chemistry operator (`diffusive_photochemistry.f90`), on the
  element nucleus face flux, since items L36c and L36d. Their stage-sum
  identities hold to 2.2e-16 and 4.3e-16 on a solved state.
- On the one fixture that admits the key with the partitioned route
  (`backup/regression/carrier_model_a_newton`, 25 passes,
  `EXHALE_PTC_DTAU0=1.0`), the state does not certify: the refusing row is
  `carrier balance He+`, 9.99e-1 at pass 1 to 7.74e-1 at pass 25 at cell
  248 (`r = 1.2013`), while the H+ row of the same state stands at
  2.256e-4 and the He++ row at 1.795e-4 against a 1e-5 gate.
- A control: on the CONTROL build's own final state (local ionization
  equilibrium, no transported helium stages) the same He+ row evaluated
  through `stationary evaluate` reads 4.151e-2, and the two builds' He II
  agree to 0.20 per cent. So the row is not broken by the transport; it is
  three and a half decades above its gate on the locally solved composition
  too.
- L36d's reading of the cause: the row's scale is the NET source, which for
  a stage whose production and loss nearly cancel is the same size as the
  residual, so the dimensionless row cannot fall below order unity however
  well the composition is solved. The carrier rows' scale in
  `steady_residual.f90` (`carrier_row_scale`, lines 843 to 874) is
  `n_H (|v| + c_s)/dr`, the element inventory moved at the signal speed;
  which scale the STAGE rows are judged on, and where it is formed, is the
  first thing the item below verifies in the source, because the L36d
  statement and the `carrier_row_scale` header describe different
  quantities.
- L36d also RE-DERIVED the 1e-5 tolerance of a stage row from a
  manufactured ionization column (order 2.886, extrapolated truncation
  7.8e-7 at the anchoring spacing, a decade above gives 7.8e-6, rounded to
  the anchor in place), so the tolerance itself is not the question.

### Why it is a defect

A certification row must be able to certify a correct state. He II in a
photoionized wind is a fast stage: its photoionization and recombination
rates are each large and their difference is the small transport term the
row exists to balance. If the row is made dimensionless by a scale that is
itself the net source, the ratio is order unity on any state, and the gate
says nothing about the transport. If it is made dimensionless by
`n_He (|v| + c_s)/dr` (the analogue of the carrier rule), then a residual
of 7.7e-1 of that means the row is genuinely unbalanced by an amount
comparable to moving the whole helium inventory at the signal speed, which
would be a solver failure and not a scale question. The two readings lead
to opposite items, and the source decides which it is. Either way the
present state (a row no composition can certify, on a fixture built to
exercise the key) leaves `Ionization transport: True` without an acceptance.

### The item (measurement first, then the decision)

1. **Read the source.** Which scale the stage rows are judged on in the
   certification (`certification.f90`, the entries L36c and L36d added) and
   in the relaxation (`diffusive_photochemistry.f90`, `carrier_row_scales`
   at line 2985 and the stage rows' `carrier_reference_scales`); whether it
   is the net source, the total production rate, the total loss rate, or
   the element-inventory signal rate. State it with lines.
2. **Measure on the fixture's solved state and on the control's state**:
   for He II at the refusing cell and over the column, the production rate
   (photoionization of He I, collisional ionization, charge exchange, the
   He 2^3S channels), the loss rate (recombination to He I, ionization to
   He III), their difference, the transport term (advective and eddy), and
   the row's present scale; the same for H II and He III. This says whether
   the row's numerator is the transport term or the chemistry cancellation
   noise, and by how much the scale differs from each candidate.
3. **Anchor by the rule.** `docs/certification_tolerance_anchoring_20260910.md`
   anchors a tolerance to the truncation error of the row's own operator on
   a refined manufactured problem. Apply it to the He II row with the scale
   candidates of step 1: for each, the manufactured-column truncation at
   the anchoring spacing and the resulting anchor. The candidate under which
   a correct state certifies AND a wrong one (the L36d RED-by-construction
   rows: charging helium to the hydrogen flux, projecting one helium stage
   alone) is refused is the scale; if two candidates qualify, the tighter
   is taken. If none qualifies, the row is reported as not certifiable on
   this fixture and the reason stated (the fixture's He II may be in
   equilibrium to the working precision, in which case the row's gate is a
   statement about rounding and the fixture is the wrong one).
4. **Decision for the user**, with the measurement beside it: adopt the
   scale of step 3 (an acceptance-interface change, so the atomic catalog's
   `Ionization transport: False` states are untouched and only key-on
   states are judged differently), or keep the present scale and record
   the row as non-certifiable for fast stages.
5. Tests: the anchoring rows (RED/GREEN), the L36d RED-by-construction rows
   still RED under the adopted scale, key-off byte identity on the four
   cases L36e uses.

### Recommendation

Do the measurement (steps 1 to 3) now as a bounded item (D3a); it needs no
decision. Decide step 4 on its memo. Do not open a solver item for the He+
row until the scale question is answered: a row that cannot fall below
order unity by construction is not a convergence failure.

### What changes for the user

Nothing with the key off. With the key on, a helium stage row may become
certifiable, or be recorded as a row the certification does not judge on
fast stages, with the reason.

## D4. The `carrier_retry` sweep-tolerance row

### The facts, READ

- `src/tests/carrier_retry/carrier_retry.f90`, row
  `one_further_sweep_leaves_the_returned_composition_within_the_sweep_tolerance`
  (line 1279): after the fixture's relaxation returns a composition, one
  further ionization sweep is taken and the relative movement of every
  "present" species is compared with the sweep's own tolerance
  `ieq_res_tol = 1e-6`. A species is "present" when its reference fraction
  exceeds `1.0d-20` (lines 1260, 1355, 1377).
- On the L36c text the row reads 1.034627e-6 against 1e-6 (RED); on its
  entry text 2.685237e-7 (GREEN). The binding species is HeH+ at 1.33e-12
  of the gas in the base cell (`f_sp` column 37, cell 1). The fixture runs
  with `Ionization transport: True`.
- L36d's diagnosis (task D): a seed that has not settled, not the
  imposition and not noise. At the binding cell the further sweep moves
  H2+ by 1.47e-8, H3+ by 1.05e-7 and HeH+ by 1.04e-6 while every parent
  moves at 1.3e-11 or below; n_e moves 5.53e-8 and H3+ carries 53 per cent
  of the cell's electrons against H+, so the chain closes on itself. A
  THIRD sweep moves the composition by 1.0085e-10, four decades below. The
  same sweep with the fractions NOT imposed moves it by 1.5e+8.

### Why it matters, and what it is not

The row asks a right question: does the composition the relaxation hands
back stand still under the sweep that produced it? It asks it of every
species above 1e-20, which is the carrier floor of the certification
contract (`docs/a2_certification_contract_20260906.md`, 1e-20 of the free
element), not a statement about which species the sweep has converged.
HeH+ at 1.3e-12 of the gas sits at the end of a three-step chain
(H2+ -> H3+ -> HeH+) whose each step amplifies the parents' movement by an
order of magnitude, so the row measures the chain's settling time, not a
defect of the operator: one more sweep and the movement is 1e-10. Under the
spelling of L36c (a fraction per nucleus) the returned composition is a different
iterate of the same chain, which is why the number moved from 2.7e-7 to
1.0e-6 without any physics changing. Raising the tolerance would be the
weakening the standing rule forbids; raising the presence threshold to
exclude HeH+ would be a tolerance in disguise unless the threshold is
defined by a physical statement.

### Options

| option | what changes | consequence |
|---|---|---|
| (1) the fixture takes the sweep to its own fixed point before measuring | the relaxation's returned composition is followed by sweeps until the movement falls below `ieq_res_tol`, and the row asserts that this takes at most N sweeps (N measured: 2 here) and that the composition then stands still; the count is the diagnostic | the row tests convergence of the chain instead of one arbitrary iterate; `ieq_res_tol` untouched; the threshold untouched |
| (2) define "present" physically | a species is present when it contributes above a stated fraction (for example 1e-6) to the cell's electron budget, or to any conserved element's budget, in the row's own terms | HeH+ (1.3e-12 of the gas, negligible electrons) drops out; the definition has to be stated where it is used and is a contract change to a test only |
| (3) record the RED as the sweep's noise and leave it | nothing | a permanently RED row in a suite, which the standing rule of `docs/worker_rules.md` (RED before, GREEN after, no tolerance chosen to pass) does not allow to stand |
| (4) raise `ieq_res_tol` or the 1e-20 | one number | forbidden: a weakening chosen to make a case pass |

### Recommendation

(1), and (2) only if (1) shows a chain that does not settle in a bounded
number of sweeps (then the fixture is exposing a real slowness and the row
should say which species). (1) keeps the row's question and adds the one
piece of information the RED was missing: how many sweeps the chain needs.

### Steps and tests

1. `carrier_retry.f90`: after the returned composition, iterate the sweep
   up to `n_max = 5` times, recording the movement of each present species
   per sweep; assert (a) the movement falls below `ieq_res_tol` within
   `n_max` sweeps (RED by construction if `n_max = 1` on the L36c text: the
   present row), (b) the movement is monotone decreasing over the sweeps
   (the chain settles rather than oscillates), (c) the species and cell that
   bind are printed. Keep the existing row's name and reference so the
   history of the number is readable, and add the count row.
2. Control: run the suite on the entry text of `carrier_retry.f90` with the
   L36c/L36d production objects (RED, 1.034627e-6) and on the new text
   (GREEN, with the count 2 and the third-sweep movement 1.0e-10 READ from
   L36d reproduced).
3. Nothing in production changes; no other suite is touched.

### What changes for the user

Nothing in any run. The suite reports how many sweeps the returned
composition needs to stand still instead of failing on the first.

## D5. What a restart pair must carry so that a molecular base face flux survives a write and a read

### The facts, READ from the L37 memo (MEASURED there on `EXHALE_3146d11b.x`)

- On six certified molecular states the cell-1 mass row read by one
  no-step re-entry (`Restart intent: stationary evaluate`) is 2.39 to 10.09
  times the value the run printed for the same cell and 16.0 to 31.2 times
  the cell's rounding floor (the tolerance is ten floors), so the evaluate
  route REFUSES states the run certified. On three certified atomic states
  of the same planet, grid and `K_zz` the ratio is 0.68 to 1.35 (L18's band
  0.78 to 1.71 met again).
- It is a transient of the re-entry: fed its own written state again, the
  reading settles by the third or fourth re-entry, and there every
  molecular state stands inside the existing anchor (0.08 to 7.5 floors).
  The atomic states are at the settled reading on the first re-entry.
- The physical cells round-trip exactly (`rho`, `v`, `p` of cells 1 and 2 to
  17 digits, the composition of cell 1 to 1.7e-16). What does not come back
  is the two inner GHOST rows, whose density and composition the loader
  re-derives and projects: ghost H I moves by 4.8e-8, the He 2^3S column by
  9.1e-6. In a molecular base the ghost carries `2 n(H2)/n_H = 0.99998`, and
  the caloric equation of state makes the base face flux a function of that
  count: scaling the ghost `n(H2)` column by `1 + eps` moves the cell-1 mass
  row linearly with slope 0.30 to 0.33 of the row's scale per relative unit
  (a ghost H2 count off by 1e-8 is four rounding floors); the same on an
  atomic ghost moves it by zero at the printed precision up to 1e-6,
  because there `p = (gamma - 1) rho e` carries no composition. Giving the
  settled state the archived ghost rows reproduces the archived reading
  exactly.
- The composition refresh of the physical cells is not the carrier: the one
  sweep moves the physical particle count by 1.3e-13, which at the measured
  slope is 4e-14 of the row.
- Two certifications inside one run already disagree at the base cells
  (5.213e-9 against 1.206e-9 at cells 1 and 3 on the reference solution,
  agreeing to four digits at the verdict cell 188).

### Why it is a defect

The certification of a state must not depend on how many times the state
has been written and read. The base ghost is the boundary's statement of
the reservoir, and the base face flux, from which the mass-loss rate is
read, is formed on it. Today the ghost that reaches the residual after a
reload is not the ghost the run certified on, by an amount the atomic base
does not feel and the molecular base feels at four floors per 1e-8. That is
a restart-contract defect, not a tolerance question: widening the anchor to
100 (which the anchoring rule applied to the round-trip perturbation would
give) would cover a restart that does not reproduce its own boundary.

### Options

| option | what changes | consequence |
|---|---|---|

### Recommendation

(1). The boundary is a stated function of the interior and the reservoir
everywhere else in the code's contract (the L26 design, `Apply_BC.f90`'s
face-state contract), and this makes the ghost composition obey the same
rule. (2) is acceptable only if (1) turns out to need a ghost quantity the
interior and the reservoir do not determine; the memo of the item says
which.

### Steps and tests

1. Read `Apply_BC.f90` and `base_boundary.f90` for which ghost quantities
   are formed from the interior and the reservoir today (density, velocity,
   pressure per L26) and which are left as the loader put them
   (composition, the He 2^3S column); read `load_IC.f90`'s projection of the
   ghost rows. State the rule the ghost composition follows in a run
   (`carrier_mass_fractions`' `X_ghost = X_N`-type rule at the base, the
   reservoir's `q_H2_base`, the element reservoir) and whether it is one
   rule or several.
2. Make `Apply_BC` form the ghost composition from that rule on every
   call, and the loader stop projecting ghost rows (it may still read them
   for the metadata check). One spelling.
3. RED/GREEN on the six molecular states of L37 and the three atomic ones:
   E1/in-run within the atomic band on all nine; the evaluate route's
   certification equal to the run's at cells 1 to 10; the two in-run

4. Byte identity with the key-independent control: `wasp_full`,
   `mol_base_handoff`, `mol_diffusion`, `lower_profile` data lines; if a

   gains the L37 measurement as the record of why anchor (6) was NOT widened.

### What changes for the user

A molecular state's certification no longer depends on the number of
re-entries; the evaluate route accepts what the run certified. If step 4
moves a golden, the movement is the ghost composition the run itself would
have formed, reported with the refresh.

whether the molecular catalog's evaluate-route products stand on a
certified reading), D2 third (a bounded boundary item with byte-identity
controls on every flowing state), D3a fourth (the measurement, no

sequenced, not parallel. D3's step 4 and D1 (a) are the
two decisions this plan asks the user to make after the measurements exist;
D2 (i), D4 (1) and D5 (1) are recommended and can be executed on the
user's word.

`LHS1140b/models/write_reproduce.py` and `src/tests/grid_and_gates/`; D2
