# The Lyman-Werner geometry: a plane-parallel table on a spherical layer

*2026-09-03. `TO_BE_DONE.md` item P47, and item E2 / section 3.4 of
`docs/open_defects_20260903_review.md`. `Update_EXHALE_stage1.md` section 150 is the
changelog entry.*


> **Status, 2026-09-03: both findings of this note have been acted on.**
> The trapping geometry is measured and the measurement now stands in the
> headers of `h2_self_shielding_table.f90` and `lyman_werner.f90` in place of
> the open-item statement; the table itself is NOT rebuilt, for the reason in
> section 6.1. The beam convention of section 6.3 IS fixed: every stellar
> beam of a run, the five FUV bands included, now reads one dayside factor
> (`global_parameters` `dayside_dilution`), and the H2 rate reads its band
> flux through `fuv_band_flux` like every other absorber of that band.


The review's question was the **sign and size**: the code applies a trapping
factor and a self-shielding table computed in a plane-parallel slab to a
spherical, outward-open atmosphere, and neither was established. Both are
below. The calculation lives in `docs/e2_lw_geometry/` (the scripts named in
section 2) and its figures are `docs/e2_lw_geometry_factors.png` and
`docs/e2_lw_geometry_rays.png`.

## 1. What geometry the installed table actually carries

Read out of the code, not out of its documentation.

### 1.1 The line-by-line half: `sigma_pump`, and `p_single`

`src/modules/lower_atmosphere/h2_self_shielding_table.f90` is generated by
`src/utils/h2_shielding_table_line_by_line.py`, which imports
`lbl_table.absolute_curves`, which imports `lbl.py`.  Its geometry is a
**plane-parallel slab with one normally incident beam**:

```
tau(nu, N) = N sum_i x_i sigma_i(nu)
pump_i(N)  = x_i (pi e^2/m c) f_i int phi_i(nu) F_nu e^-tau /(h nu) dnu
```

The attenuating column `N` is the column **along the beam, between the
illuminated face and the point**.  There is no angular integration, no diffuse
component and no geometrical dilution: one ray, one direction, one column.
Level populations are LTE at the imposed `T`; line overlap is inside `tau`.

### 1.2 The trapping: `p_eff/p_single`

`h2_shielding_table_line_by_line.trapping_ratio` reads `p_eff/p_single` node by
node from the 27 CLOUDY runs of `src/utils/h2_shielding_cloudy_decks/` and
multiplies it into `p_single`.  The decks
(`t1300_n13.in` and its siblings) carry `stop H2 column density 21.7`,
`iterate 1`, and no `sphere` keyword, so the geometry is CLOUDY's default
plane-parallel one, illuminated on one face.

What "trapping" means there: a fluorescent decay photon of the line `u -> l` is
re-absorbed with probability `1 - Ploss`, and the re-absorption is folded into
the branching

```
p_eff = D / (D + sum_l A_ul Ploss_ul)
```

rather than followed as a re-emitted photon.  `Ploss` is CLOUDY's escape-or-destruction
probability, formed one transition at a time, for the column that lies
between the point and the faces of the slab.  `p_single = D/(D + sum_l A_ul)` deliberately
omits it, because a trapped decay plus its re-absorption moves one molecule down
and another up and so cancels out of the count of decays per dissociation.

### 1.3 Which column the code feeds the table

`src/modules/radiation/util_ion_eq.f90:290` calls

```fortran
call calc_column_dens_one(nH2, NH2col)
```

and `calc_column_dens_one` (`src/modules/functions/utilities.f90:372-383`) is

```fortran
Ncol(N+Ng) = dr_j(N+Ng)*R0*nsp(N+Ng)*opa_pf(N+Ng)
do j = N+Ng-1,1-Ng,-1
    Ncol(j) = Ncol(j+1) + nsp(j)*dr_j(j)*R0*opa_pf(j)
enddo
```

i.e. a **purely radial** column, accumulated from the outermost cell inward,
with the same rectangle rule every other absorber column uses.  It is the column
directly above the cell.  No stellar zenith angle enters, and there is no slant
or Chapman correction anywhere in the path.  So the code identifies "column from
the illuminated face of the slab" with "radial column above the cell", which is
the **substellar ray** of a parallel beam.

### 1.4 Which flux the code applies

`lyman_werner_dissociation_rate(F_LW, N_H2, T, n_H, tau_cont)` uses `F_LW`
directly, and `fuv_band_flux(ib_LW)` returns `F_LW_star`, documented in
`parameters.f90` as the band flux **at the planet's orbit**.

**No dayside factor is applied to it.**  In the same run,
`set_energy_vectors.f90:199-224` multiplies `F_XUV` by 0.5 under
`2D approximate method: Rate/2 + Mdot/2` (0.25 under `Rate/4 + Mdot`), and
`lya_rt.f90:133-140` applies the same `xi` to the stellar Ly-alpha beam.
`fuv_band_flux` applies it to none of the five FUV bands -- including `ib_B2`,
which returns the very `F_Lya_star` that `lya_rt` halves on the other path.
This is stated as a finding in section 6.3; it is a within-run inconsistency of
convention, not a table problem.

## 2. Design of the matched comparison

The requirement of E2 is a slab/sphere calculation with **identical molecular
data**.  It is met by construction: both geometries are evaluated from one
kernel, built from the same Abgrall, Roueff & Drira (2000) line list, the same
LTE populations, the same Voigt profiles and the same frequency grid that
generated the installed table (`lbl.py`, imported directly).

### 2.1 The kernel (`e2_kernel.py`)

For a temperature `T` and a grid of columns `N` along **one ray**:

| symbol | meaning |
|---|---|
| `sigma_pump(N)` | pumps per unit incident band photon fluence [cm^2] |
| `p_single(N)` | pump-weighted mean of `p_dis` of the upper levels |
| `W[u, N]` | fresh pump rate into upper level `u` |
| `Aesc[u, N]` | `sum_l A_ul P_ul(N)`, the escaping decay rate of `u` along one ray of column `N` |

`Aesc` is the entire geometry-independent part of the trapping.  An escape
probability averaged over directions is **linear in the transmission**, so for
any quadrature `{N_k, w_k}` of ray columns over solid angle

```
sum_l A_ul <P_ul>_Omega = sum_k w_k Aesc[u, N_k] ,
```

and slab and sphere differ **only** in `{N_k, w_k}`.

`P_ul` is a single-flight escape probability under **complete redistribution**:
the fluorescent photon is emitted with the absorption profile of its own decay
line and sees the total H2 line opacity of the same LTE populations, line
overlap included.  Decay lines longward of 1200 A see no H2 line opacity and
escape freely.  The Abgrall decay lists do not always sum to `Gam (1 - p_dis)`;
the missing branch is assigned to free escape (the dropped lines are weak and
lie longward of the pumping window) and an over-complete one is scaled back.

Then

```
p_eff = sum_u W_u D_u / (D_u + sum_k w_k Aesc[u, N_k])  /  sum_u W_u ,
```

with `W_u` evaluated at the star-ward column of the point, because the stellar
beam is what sets the distribution of fresh pumps over upper levels.

### 2.2 The two geometries (`e2_geometry.py`)

* **slab** -- `N(mu) = N_rad/mu` for `mu > 0`, no escape inward.  This is the
  geometry of the installed trapping ratio (illuminated on one face, closed on
  the other) and of its line-by-line pumping (normal incidence).
* **sphere** -- `N(mu)` is the real ray integral through `n(r)`, blocked when
  the ray reaches the opaque base.  Path length is the integration variable, so
  the turning point of an inward ray is a smooth minimum and the
  `1/sqrt(rho^2 - p^2)` of the radial form never appears.

The same ray integral serves the stellar beam, because a parallel beam
direction and an escape direction are the same geometrical object.

### 2.3 The atmosphere

The hot-Uranus gate rung
`<scratch>/ladder3/runs/heh0p0793/output`, physical cells only.  `R_p = 0.49
R_J = 3.503e9 cm`, `M_p = 0.0457 M_J`, `g(R_p) = 472 cm s^-2`.  The molecular
layer runs `N(H2) = 3.9e20` at the base down to `1e13` by `r = 1.36 R_p`, at
`T = 590-2300 K` and `n_H = 1.1e13` down to `1.6e9 cm^-3`.  `H/r = 0.014-0.024`
through the H2-bearing part, i.e. `r/H = 41-55`, so the grazing column is
capped at roughly `sqrt(pi r / 2H) = 8-9` times the radial one.

**That run has the Lyman-Werner option OFF** (its setup report says
`WARNING H2 Lyman-Werner photodissociation OFF: no "Stellar LW flux" key`).
It is used as a representative molecular-base structure; it is not a
self-consistent LW solution, and the factors below are evaluated on it rather
than iterated with it.

### 2.4 Three factors

| factor | definition |
|---|---|
| `f_trap` | `p_eff(sphere)/p_eff(slab)` at the code's own star-ward column.  **This is the P47 factor**: the trapping is the only ingredient of the installed table whose geometry differs from ours, and this is its size and sign with everything else held fixed. |
| `f_curv` | `<sigma_diss>_sphere / <sigma_diss>_slab`, both over the same angular quadrature.  What curvature does to the angular average of the stellar beam. |
| `f_shell` | `<sigma_diss>_sphere` over the full `4 pi`, divided by `sigma_diss(N_radial)`, the value the code uses. |

`f_shell` is **not** a slab error.  A parallel beam's substellar ray column is
the radial column, in a sphere exactly as in a slab, so the slab table is exact
for the substellar ray.  `f_shell` is the difference between the substellar ray
the code evaluates and the shell average a 1-D spherically symmetric rate needs.
Its optically thin limit is 1/2, because the night side is dark.

### 5.1 The sign of the trapping error is settled: the slab over-traps

`f_trap <= 1` everywhere, monotonically in height.  The spherical layer lets
more fluorescent photons out than the slab does, so `p_eff` is smaller, so
`sigma_diss = p_eff x sigma_pump` and the photodissociation rate are smaller.
**The installed table therefore over-predicts the Lyman-Werner rate**, by
0.2 per cent at the base, 7-10 per cent through the H2-bearing layer, and up to
20 per cent at the top where H2 is already negligible.  Rate weighted over the
layer, 6.5 per cent.

The mechanism is visible in `docs/e2_lw_geometry_rays.png`.  The spherical ray column tracks
the slab's `1/mu` down to `mu ~ 0.3` and then **saturates** at 8-12 times the
radial column where the slab diverges, and it stays finite past `mu = 0` until
the ray strikes the opaque body.  Escape in both geometries is dominated by the
near-radial directions, where the two columns are identical -- which is why the
effect is small -- and the difference is entirely the near-tangential and
just-past-terminator directions the sphere keeps open.

The height dependence follows `r/H`, not the column: at the base `r/H = 41` and
the sphere is a slab to 0.2 per cent (the escape hemisphere closes exactly at
`mu = 0` and the grazing cap is at 9 times a column that is already `4e20`); at
`r = 1.36 R_p`, `r/H = 16`, the cap is at 5 times a column of `1e13`, and the
extra escape is worth 20 per cent.

### 5.2 Curvature of the stellar beam is small

`f_curv = 0.98-1.06` through the H2 layer.  Two curvature effects almost
cancel: the sphere shortens the near-tangential beam path relative to
`N_rad/mu` and admits a lit sliver past the terminator, which raises the average
pumping by 6-49 per cent; and the sphere traps less, which lowers `p_eff`.  In
the product they cancel to a per cent or two.

### 5.3 What is NOT a slab error, and is the larger number

`f_shell = 0.20-0.33` in the H2 layer.  The code evaluates the substellar ray
and applies the full band flux at the planet, so its Lyman-Werner rate is
3.8-4.4 times the shell average that a 1-D spherically symmetric H2 budget
needs.  The optically thin limit of `f_shell` is 0.5; the extra factor 1.5-2.5
is the shielding of the longer slant columns away from the substellar point.

This has nothing to do with the slab table, which is exact for the substellar
ray in either geometry.  It is a question of the beam convention -- and the
same run halves its XUV and Ly-alpha for exactly this reason and does not halve
its Lyman-Werner band (section 1.4).

## 6. Recommendations

### 6.1 The table does not need replacing for geometry

The trapping geometry error is one-signed and bounded by 20 per cent, is 7-10
per cent where H2 actually lives, and is **smaller than the 20-40 per cent
spread between two escape-probability methods in the same slab** (section 3).
Rebuilding the trapping cube in spherical geometry would move `sigma_diss` by
less than the uncertainty already inside it.

What is worth doing instead, in order of value:

1. State the geometry and its measured bound in the module header, replacing
   "an open item of TO_BE_DONE.md" with the number: *the plane-parallel trapping
   over-predicts `p_eff` by 0.2 per cent at `r/H = 41` and by up to 20 per cent
   at `r/H = 16`, one-signed, 6.5 per cent rate weighted over a hot-Uranus
   molecular layer.*
2. Keep the E2 provenance name (`slab_surrogate` or equivalent) the review asks
   for, since the trapping is a slab quantity by construction.
3. If the trapping is ever revisited, the leading term is the **method**, not
   the geometry: a self-consistent line-transfer solution for the fluorescent
   photons, checked against CLOUDY and Meudon, is worth 20-40 per cent, where
   the geometry is worth 7.

### 6.2 If an extra axis is ever added, it is `r/H`, not `r`

`f_trap` is controlled by the ratio of the local scale height to the radius,
because that is what sets the grazing cap `sqrt(pi r / 2H)` and the blocked
solid angle `arcsin(R_base/r)`.  A fourth axis in `H/r` (or, equivalently, in
the Chapman grazing enhancement) would carry it.  On the present evidence it is
not warranted: over the H2-bearing layer the whole axis spans 0.90-1.00.

A cheaper alternative with the same content: leave the cube alone and apply an
analytic multiplier `f_trap(H/r, N_H2)` fitted to the table of section 5,
default off.

### 6.3 The beam convention: a separate finding, and it is fixed

`fuv_band_flux` (`src/modules/radiation/util_ion_eq.f90`) returned
`F_LW_star`, `F_FUV_B1`, `F_Lya_star`, `F_FUV_B3`, `F_FUV_B4` **raw**, with no
`appx_mth` dayside factor, while `set_energy_vectors.f90` halved `F_XUV` and
`lya_rt.f90` halved the stellar Ly-alpha beam under the same key. Worse, the
H2 dissociation rate did not even go through `fuv_band_flux`: it read
`F_LW_star` directly, so the band had one owner for the oxygen photolysis and
the photon ledger and another for the rate itself.

Under `2D approximate method: Rate/2 + Mdot/2` -- the setting of the
hot-Uranus gate and of the whole regression matrix -- the H2 Lyman-Werner rate
therefore stood a factor 2 above the convention the same run applied to every
other band, and `F_Lya_star` was halved on one path and not on the other.

Section 150 makes it one definition, `global_parameters dayside_dilution()`,
read by the XUV grid, by the stellar Ly-alpha beam, and by all five FUV bands,
with the H2 rate reading its flux through `fuv_band_flux` like every other
absorber of that band. The keys keep their meaning -- the band flux at the
planet's orbit, whether stated or integrated from the spectrum file -- and the
dilution is applied where the beam is used, so the setup report and the
resolved dump still state the number the run was given. The setup report gains
one line naming the factor.

The physically correct shell-average factor for a shielded band is not 0.5
either; it is `f_shell = 0.20-0.33` in the H2 layer (0.5 only in the optically
thin limit). That refinement is the separate default-off key of section 6.4,
not part of the convention fix.

**What the fix moves.** Only a run that carries an FUV band flux can move, and
of the ten regression matrix cases only `mol_lyman_werner` does.
`wasp_full` (He 2^3S, metals, `Stellar Lya flux`, `Rate/2 + Mdot/2`) and
`mol_base_handoff` (molecular, no FUV flux) are byte-identical in every output
file. On `mol_lyman_werner`'s 12000-step snapshot the H2 front at
`x(H2) = 1e-3` moves out from 1.0730 to 1.0812 `R_p`, the H2 column through
the layer rises 13.4 per cent, `x(H2)` rises by up to 4.3 times right through
the front, and `Mdot` at 2 `R_p` falls 4.1 per cent (`log10 Mdot` 10.47 ->
10.44). Those are snapshot values: that case is a fixed-step relaxation, and
the Newton finish it would need for a quantitative `Mdot` had not been reached
when this note was written.


### 6.4 The shell average as an option

`f_shell` is reproduced without a fitted constant by

```text
alpha   = -d ln sigma_diss / d ln N     at the cell's radial column
C       = sqrt(pi r / 2H)               the grazing cap of a spherical layer
f_shell = (1/2) int_0^1 (mu^2 + C^-2)^(alpha/2) dmu
```

using the smooth Chapman form `Ch(mu) = (mu^2 + C^-2)^(-1/2)`, which is 1 at
the substellar point and `C` at the limb. Against the direct spherical ray
integration of section 5 this closure is high by 4-10 per cent over the
H2-bearing layer (`N_H2 >= 1e18`) and lands within -15/+18 per cent over the
whole layer; it runs low where the layer is optically thin, because it drops
the lit region past the terminator, and there the option barely changes the
rate anyway. Both inputs are quantities the run already holds: `alpha` from
two lookups of the installed table, `C` from `T`, `g` and the layer's mean
molecular weight.

It is a default-off key because it changes the meaning of a converged solution
and because the closure is calibrated on one planet.

## 7. What was not established

* **The absolute trapping.** This work does not settle whether CLOUDY's
  `p_eff/p_single` or this one is right; it settles the difference between two
  geometries inside one method.  The 20-40 per cent method spread of section 3
  stands as the dominant uncertainty in `p_eff`.
* **Frequency redistribution.** Complete redistribution only, as the task
  scoped it.  Partial redistribution would raise escape in the damping wings,
  and it would do so in both geometries; whether it does so by the same factor
  is untested.
* **Multiple scattering.** A single-flight escape probability, in both
  geometries; no source-function iteration for the fluorescent photons.  The
  same objection applies to the way CLOUDY treats one transition at a time,
  but not identically.
* **Self-consistency.** The rung profile was computed with the Lyman-Werner
  option off, so the factors are evaluated on a structure, not iterated to a
  fixed point.  Applying `f_trap` inside a converged LW run would change
  `n(H2)(r)` and hence `f_trap` itself; the feedback is second order at
  `f_trap = 0.93` but is untested.
* **One planet, one rung.** Only the hot-Uranus gate.  `f_trap` is a function of
  `r/H`, which for a hot Jupiter base is larger (thinner layer relative to the
  radius), so the geometry error there should be **smaller** than the numbers
  above; that has not been computed.
* **The `f_shell` decision.** The number is measured; which convention EXHALE
  should adopt is not decided here.
