# P5a: the capacity contract of a certification report

Item P5a of [PLAN_20260919_rev1.md](PLAN_20260919_rev1.md) (section 1, R4;
[PLAN_20260919_review.md](PLAN_20260919_review.md) section 7.1). Written
2026-09-19 (KST). Every number below is MEASURED here or READ from the file
named beside it.

## 1. The defect

`add_entry` in `src/modules/time_step/certification.f90` returned silently
when the report already held `cert_max_entries` entries, and every entry
writer then assigned into `rep%e(rep%n)`, which in that state is the
PREVIOUS entry. The report could therefore carry one equation's name over
another equation's measure, tolerance and verdict, and a certification
written from it states a verdict about a set of equations it does not name.

MEASURED here through the public entry writer, on the entry text
(`certification_capacity.x` built against the entry-text objects):

```text
filled entry_count=32
filled last_name=ionization stage nucleus sum H
filled last_measure= 4.200000E+01
after entry_count=32
after last_name=ionization stage nucleus sum H
after last_measure= 7.000000E+00
silent_overwrite=T
```

The hydrogen entry keeps its name and carries the helium equation's measure.

## 2. The contract as implemented

`add_entry` is the one place a report gains an entry and now the only place
an entry index comes from. It returns `ient`, the index of the entry it
created, and every entry writer assigns each field through that index. The
invariant is that an entry writer only ever addresses the entry its own call
created; addressing `rep%n` instead is what made the defect available.

An entry that does not fit stops the run, loudly and before any field is
written, so the entries the report already holds stand as they were. The
refusal names the equation that did not fit, the capacity, and the entry
that stands last (MEASURED, the same driver on the measured build, exit
status 1):

```text
 (certification) REPORT FULL: the equation "ionization stage nucleus sum He" does not fit
 (certification)   capacity cert_max_entries = 32 entries, all of them in use
 (certification)   last entry unchanged: ionization stage nucleus sum H  max= 4.200000E+01
```

Both halves are needed. The index removes the mechanism; the stop removes
the case in which a report would be written with fewer equations than the
run solves.

## 3. The capacity

The number is unchanged at 32 and is no longer a literal. It is now formed
from the counts that set it, so it follows the inventory:

| kind of equation | entries |
|---|---:|
| hydrodynamic mass, momentum, energy rows | 3 |
| transported carrier balances (`n_carrier_max`) | 7 |
| ionization stage nucleus sums, H and He | 2 |
| He/H partition transport balance | 1 |
| trace element transport balances (`n_melem`) | 10 |
| He 2^3S and H(n=2) level balances | 2 |
| eliminated-species closures (`n_system_variant`) | 7 |
| **total** | **32** |

MEASURED: a program printing the parameter reads `cert_max_entries=32`, the
value the entry text carried as a literal.

MEASURED, the largest configuration: the report of a run with the ionization
state transported and metals on holds 32 entries, the capacity exactly. READ
from the run logs the binary of record left in `backup/regression/`:
`iontrans_metals`, `hp_zero_seed`, `hp_trace_seed` and `hp_front` print
`active equations 11 of 32 in the inventory`; the cases without transported
stages print `of 30`. The capacity is therefore exactly consumed today, with
no free slot, which is why the defect was one added equation away from
production and not only a property of an artificial input.

Raising 32 to another constant is not the repair. It leaves the same silent
overwrite available one equation later, and it hides that the number is not
free: it is the size of the inventory. A derived count cannot drift from the
builder, and the stop states what to do if it ever does.

## 4. Tests

`src/tests/certification/`:

- `certification_contexts.f90`, row (j),
  `a_report_holds_exactly_the_equations_of_the_inventory`: a report filled
  to capacity through the public writer, hydrogen on the odd indices and
  helium on the even ones so that the two elements carry different names,
  tolerances and verdicts, and each entry a cell of its own. The last
  equation that fits is complete and correct, and the name, measure, cell,
  tolerance and verdict of every entry belong to one equation.
- `certification_capacity.f90`, a program of its own: one equation past a
  full report. The refusal stops the process it runs in, so it cannot be
  asserted from inside it; `run.sh` reads the exit status and the text.

RED against the entry text: `one_equation_past_a_full_report_stops_the_run`
(status 0), `the_refusal_names_the_equation_and_the_capacity` and
`a_refused_entry_overwrites_nothing` all FAIL, with the overwritten sentinel
printed beside the first. GREEN on the measured build: all three PASS and
the whole suite passes.
