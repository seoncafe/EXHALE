# P6d and P6e: the charge-exchange turnover guard and the elemental base flux record

Items P6d and P6e of [PLAN_20260919_rev1.md](PLAN_20260919_rev1.md), from
sections 9.4 and 9.5 of [PLAN_20260919_review.md](PLAN_20260919_review.md).
Both are contract items: one entry point of `charge_exchange.f90` did not say
which cell it was answering for, and one public record of
`binary_element_diffusion.f90` did not say which evaluation it came from.
Every number below is MEASURED here unless it is marked READ.

## Verdict

**P6d.** The missing guard is real and is now in place. `cx_add_to_turnover`
takes the temperature of the cell whose turnover it is bounding and stops the
run through `cx_require_cell`, with the message `cx_add_to_fvec` and
`cx_add_to_jac` use, when that cell is not the one `cx_set_cell` filled the
rate coefficients at. **No production call with stale rates exists on the runs
measured here, and the reason is structural rather than lucky**: every
production path that reaches the turnover installs the cell first. The measure
is stronger and narrower than "no mismatch was seen": on the five runs
instrumented the entry point **was not called at all**, so the runs say nothing
about mismatch and everything about where the path lies. Section 2 gives the
evidence and the positive control that the probe fires.

The cell is OPTIONAL in the interface, and that is the item's one loose end:
two of the three call sites live in `ionization_equilibrium.f90`, which another
worker owns for the duration of this item, so they could not be given the
argument here. A call that states no cell is still refused when the thread
holds no cell at all. Section 2.4 gives the three one-line call-site changes
and what each needs before it is made.

**P6e.** The record is now a statement about one evaluation, and it carries
both halves of the flux, their sign convention and their units.
`element_base_diffusive_flux` is replaced by `element_base_flux`, a record with
the evaluation that wrote it, the advective and diffusive halves at the base
face and at the first solved face, and a report routine that says "no element
operator evaluation has written a record" instead of printing an
uninitialized number.

**One thing the record now shows that the old one hid.** The old
`element_base_diffusive_flux = Jf(0)` was **identically zero on every call**,
not small: the gradient and drift coefficients are built on faces 1..N-1 only
and faces 0 and N are left at zero (`drift_and_gradient_face_coefficients`,
READ, lines 2219 to 2240), so `element_face_flux` at face 0 returns zero
whatever the state. The flux the Dirichlet reservoir composition drives is at
the FIRST SOLVED FACE, face 1, and it is the number the plan quotes for
`lower_profile`. Both faces are in the record, each as its own number.

The elemental budget does not move: the data rows of `wasp_full`,
`mol_metals`, `lower_profile` and `mol_diffusion` are byte-identical between
the control build and the measured one (section 4).

## 2. P6d: is there a production call with stale rates?

### 2.1 What was instrumented

A private copy of the tree (scratch only) was given a `cx_add_to_turnover`
that takes the cell, counts its calls, and WRITES a line instead of stopping
when the cell it is asked for is not the one loaded; the three call sites were
given `ieq_cell%T_K` in that copy alone. The production tree's call sites were
not touched.

### 2.2 What the runs found

MEASURED, single threaded, with the instrumented binary:

| case | steps | turnover calls | stale calls |
|---|---|---|---|
| `wasp_full` | 400 | 0 | 0 |
| `mol_metals` | 12000 (its pinned steps) | 0 | 0 |
| `mol_carrier` | 12000 (its pinned steps) | 0 | 0 |
| `hp_front` | 100 (its pinned steps) | 0 | 0 |
| `iontrans_metals` | the stationary solve, 90 outer passes | 0 | 0 |

The entry point was not reached at all. That is not an accident of these
cases: READ, `normalized_reaction_residual` is the acceptance measure, and the
two branches that reach the turnover inside it are entered only when a cell
solve has to be rechecked (a clamped iterate, a non-root, a constrained
continuation), while the two isolated entry points that evaluate it on a
finished state, `ionization_closure_residual_cell` and the column loop beside
it, both call `ieq_install_cell(j)` first, which calls `cx_set_cell` for that
cell. So the paths that reach the turnover load the cell on the way in.

### 2.3 The probe fires

A measurement of zero is worth nothing without a positive control. The
refusal program of section 3, linked against the INSTRUMENTED objects, prints

```
 INSTRUMENT turnover calls=  1  stale= 0  asked=   10000.000000000000
 INSTRUMENT turnover calls=  2  stale= 0  asked=   6000.0000000000000
 INSTRUMENT turnover stale asked=  10000.000000000000  loaded=  6000.0000000000000
```

so both the counter and the mismatch line reach the log when the call is made.
The zeros above are therefore "not called", not "not printed".

### 2.4 The loose end: the three call sites

The guard is only as strong as the callers that use it. The three changes are
one line each:

| file, line | call today | what it becomes | what it needs first |
|---|---|---|---|
| `ionization_equilibrium.f90` 3913 | `cx_add_to_turnover(cxb, el_tot)` | `cx_add_to_turnover(cxb, el_tot, ieq_cell%T_K)` | owned by another worker in this session; the instrumented run above already passed `ieq_cell%T_K` there and no mismatch was raised |
| `ionization_equilibrium.f90` 3987 | `cx_add_to_turnover(srow, el_tot)` | the same | the same |
| `constrained_chemical_equilibrium.f90` 800 | `cx_add_to_turnover(cxb, el_tot)` | `cx_add_to_turnover(cxb, el_tot, ieq_cell%T_K)` | NOT made here: `set_turnover_scales_at_field` is on the molecular rung path, which none of the five runs above entered, so it has not been measured that the cell loaded there is `ieq_cell`'s. Making it a stated cell without that measurement would turn an unexercised path into an abort |

## 4. P6e: the base flux record

### 4.1 What the record holds

```fortran
type, public :: base_element_flux_record
   integer :: evaluation = 0
   integer :: first_solved_face = 0
   real*8  :: advective_base_face = 0.0d0
   real*8  :: diffusive_base_face = 0.0d0
   real*8  :: advective_solved_face = 0.0d0
   real*8  :: diffusive_solved_face = 0.0d0
end type base_element_flux_record
```

Both halves are helium element mass fluxes in g cm^-2 s^-1, positive OUTWARD.
The advective half is the state's own face mass flux, the face mean of rho and
of v, times the reconstructed upwinded face helium mass fraction of
`species_face_fraction`, which is the face composition the Runge-Kutta stages
put on that face; the face counters that routine keeps are saved and restored
around the evaluation, because they are statements about the trajectory and a
budget entry must not add to them. The diffusive half is the operator's own
`element_face_flux` at that face. `evaluation` counts the operator evaluations
that produced a composition, so a caller that notes the count before its own
step can tell this record from an older one, and `evaluation = 0` is "no
operator has run", which `element_base_flux_report` states in words.

### 4.2 The measured fluxes

MEASURED with a build that prints the record at every evaluation (scratch
only; the delivered code prints nothing), at the last evaluation of each run,
single threaded:

| case | evaluation | base face 0 advective | base face 0 diffusive | first solved face | face 1 advective | face 1 diffusive |
|---|---|---|---|---|---|---|
| `lower_profile` | 12000 | 6.2852034E-10 | -0.0000000E+00 | 1 | 6.3194353E-10 | -5.5826627E-13 |
| `mol_diffusion` | 12000 | 4.9280258E-10 | -0.0000000E+00 | 1 | 4.9389383E-10 | -3.0298600E-13 |

All six columns are g cm^-2 s^-1, positive outward, so a negative diffusive
half is helium settling INWARD across that face while the gas carries it
outward. The base face's diffusive half is a signed zero, which is what
`-Agrd (X_r - X_l) - Bdrf [X(1-X)]` returns with both coefficients zero.

For `lower_profile` the plan's earlier figure for face 1 was -5.57e-13
g/cm^2/s (READ, `PLAN_20260919.md` line 172); the number measured here at the
last evaluation is -5.5826627E-13, and at evaluation 1079 of the same run it
was -5.5585635E-13, so the diffusive half at that face is steady to about half
a per cent over the relaxation.

**The advective half is not steady, and that is the item.** On the same
`lower_profile` run it reads +4.4698261E-08 at evaluation 1079,
-3.3467477E-10 at evaluation 11220 and +6.2852034E-10 at evaluation 12000: the
base sound wave of that column turns the base face flux over, in sign, between
evaluations. A record with no evaluation on it can therefore be wrong by more
than its own size, and by its sign, without anything looking amiss.

### 4.4 What was NOT changed, and what it would move

`element_flux_profile.txt` keeps its columns and its row range (`j = 1, N-1`).
Printing the base face into it would add a row at `j = 0`, and with a
lower-atmosphere profile in use that row would also enter the window
reduction (`reduce_element_flux_windows`), which feeds the overlap and steady
flux medians and spreads of `write_resolved_config`. That is a change to a
reported product and is left for a golden-refresh decision, as the plan asks.
The record above carries the same two numbers without touching a product.

## 6. Noticed outside the scope, not fixed

- The D2b text says the Dirichlet base composition "drives a diffusive flux
  through the base face" and that `element_base_diffusive_flux` records it
  (READ, `lhs1140b_stationary_D2b_20260918.md` lines 153 and 368). The
  discretization puts that flux at face 1, not face 0, and the number recorded
  at face 0 was identically zero. The record here carries both faces; the memo
  is a record of its own session and was left as it stands.
- `element_base_flux` has no reader in the tree: nothing reports the base
  elemental budget entry anywhere. The stationary route is where it would
  belong.
