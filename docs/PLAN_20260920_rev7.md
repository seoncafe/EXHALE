## 3. Mode R and Mode C

Two ways to work on a case, both legitimate, never confused in a report.

**Mode R, the current operator on an immutable checkpoint.** Evaluate the
current operator on a stored generation, optionally including ONE explicitly
identified disposable update followed by restoration, publishing nothing.
Record the input state, the operations actually performed and the output
identity. `load_IC` detects that the restart
was written under another boundary model, rebuilds the boundary from the
physical column and this run's reservoir, solves the ghost composition to the
current model's own seed and fixed point, and states that the residual is not
the residual the restart was written with (INSPECTED, `load_IC.f90:1278-1291`).
That makes Mode R a well-defined experiment of the CURRENT operator on an OLD
state. It answers: is the residual reproducible, which terms change when the
boundary is rebuilt, where the current operator places the failing rows.
It does not answer anything about the current branch, and it is never a
reproduction of the historical certificate.

**Mode C, a retained trajectory on the current branch.** Advance a retained
trajectory under the current solver, with a declared budget and a recorded
ending. A published or certified checkpoint is not required for that
trajectory to be evidence. Required for any claim about convergence on the
current branch, for continuation, and for solver performance comparisons.

Every result prints, beside the number: the mode, the binary identity, the
boundary model identity, the reservoir and input hashes, the generation
identity, whether any physical step was taken, and **the effective parsed
configuration**. The last is not the input file: several options are derived
after parsing, for instance `input_read.f90:2193`,
`if (.not. carrier_transport_stated) carrier_transport = thereis_oxychem`, so
a case can transport carriers although its input never states it. Record the
parser's own resolved summary, machine readable, or the setup report it
writes.

**One classification, used in every table and every report.** The label
follows the experiment performed, never whether a checkpoint was published.

| activity | label |
|---|---|
| reading the logs and stored products of a past run | historical audit, carrying the HISTORICAL executable identity; it says nothing about the current operator |
| one evaluation, or one restored disposable update, from an immutable checkpoint under the current binary | Mode R, stating whether an update was performed and from which restored snapshot |
| advancing a sequence of passes under the current solver | Mode C, including a short diagnostic trajectory |

Mode C does not mean a long campaign and does not need a certified
checkpoint. A short controlled failed solve is useful evidence as long as its
initial state, its budget and its ending are preserved. Publishing a
diagnostic checkpoint stays distinct from certifying a solution.

Stage A0, Stage A, Stage B, the coupled Stage B and the M2 audit are Mode R,
restored disposable probes. The M1 alternation audit of section 9.2 advances
passes and is therefore Mode C, however short. The coupled trial of section
9.4 and Stage F are Mode C.

Reading a stored artifact and the identity of the experiment that artifact
records are two different things. Keep that experiment's executable, state and
mode metadata with it; a filename does not establish whether the current
operator produced it, and writing a newly generated diagnostic result into a
log does not make the experiment behind it historical.

### 4.2 The gate every diagnostic run passes

A diagnostic is "executed" only if all of these are recorded:

1. the complete environment set actually in force, including variables set to
   `0`, and the mode (R or C);
2. the file the diagnostic was expected to write, its existence, its nonzero
   size, its header and its row count;
3. the state or generation identity the output belongs to, and whether the
   rows came from the final state, a discarded trial or an intermediate
   evaluation;
4. the exit class of the run.

"No output", "timeout before the checkpoint" and "measurement unresolved" are
three distinct results and none of them is a pass. This applies in particular
to `EXHALE_CARRIER_ROW_TERMS=1`, whose file is written from the certification
path (`certification.f90:1492`): a run that ends before a certification writes
nothing at all.

**An existence check is necessary and not sufficient.** INSPECTED,
`diffusive_photochemistry.f90:2788-2790`: the writer opens the fixed path
`output/carrier_row_terms.txt` with `status='replace'`, returns silently when
recording is off or its arrays are unallocated, and its header describes only
"the last assembly", with no generation or evaluation identifier; and the
certification restores its isolated workspace without restoring or removing
the file. So a failed run can leave a valid-looking file from an earlier one,
and several evaluations of one run overwrite the same path. The requirements
are therefore operational:

1. run every diagnostic invocation in its own output directory, leaving the
   existing products untouched;
2. archive the file with a sidecar naming the invocation, the input state, the
   executable, the evaluation stage and the exit status;
3. where a run performs several evaluations, either emit an identifier at the
   writer or capture the intended evaluation explicitly. A modification time
   is weak evidence of which state produced the rows;
4. if execution ends before the intended evaluation, record that outcome even
   though another evaluation produced a file. An external termination and the
   last completed inner solve are two separately identified observations, and
   neither is promoted into a completed outer result.

## 5. The first read-only measurements

### 5.1 Residual-route equivalence, before anything else

Three paths evaluate a residual, and INSPECTED they do NOT differ in the way
rev6 implied. The loaded-state route behind `EXHALE_RESIDUAL`
(`EXHALE_main.f90:1283`) and the Newton route's `eval_residual`
(`steady_newton.f90:4315`) call the SAME `assemble_residual`, so their
hydrodynamic rows come from one assembly and a difference between them cannot
be a different row assembly. What can differ between them is the composition
and closure policy (which sweep count, whether the state is refreshed), the
assembly selector of section 13.6, and the module state each leaves behind.
The marching operator is the one genuinely different path: it uses
`reconstruction_continuation_rhs` directly (`EXHALE_main.f90:2267`, `:2312`,
`:2348`) and advances a state instead of forming a stationary row.

At one checkpoint, evaluate each where it applies and compare, term by term: the
mass, momentum and energy row vectors; the base and outer ghost states; the
face mass fluxes; the heating and cooling arrays; the composition and particle
counts; the carrier and element row vectors.

If the paths are meant to state the same stationary equations, every
difference is explained term by term. If they are deliberately different maps,
this document names which map each certificate and each derivative test uses.
Until that is written down, a comparison of two norms from two routes means
nothing.

**The protocol must not mutate the state.** Each route prepares derived
quantities and may leave module workspaces, composition, caches, the ghost
state or the reconstruction mode different from how it found them. For every
route record, before and after: the conserved state and composition hashes,
the ghost state and the base boundary cache, the particle counts, temperature,
heating and cooling, the face fluxes with the reconstruction and limiter mode,
the composition sweep count and the seed hash, and every module cache or
branch identifier in force. Save the pre-route state and restore it before the
next route. Running the three paths in sequence without restoration can make
state mutation look like operator disagreement, which is exactly the ambiguity
this measurement exists to remove.

The marching operator advances a state. If it cannot be evaluated without
advancing time, evaluate its right-hand side once at the frozen state and
label the comparison as a right-hand side comparison, not as a stationary
residual comparison.

The result is a term-by-term map, never three norms.

### 5.2 Stage A, repeatability

`EXHALE_RESID_DETERMINISM` (`EXHALE_main.f90:1378`) already evaluates the
control twice, runs three trials, returns to the control, performs a
deliberately discarded evaluation, takes a probe, and evaluates the control
again, reporting which entries of the full vector moved.

Requirements added by rev1 and kept: compare every component, not the row
maxima; fix BLAS threading as well as OpenMP threading and repeat at each
count before comparing counts; do not call a thread-count difference a
reduction-order effect, since shared state, a race, initialization and
branch-sensitive chemistry produce it too; and a failure here is a reason to
distrust derivatives, not proof that the model lacks a state function.

## 6. Stage B, the accuracy of the action

1. Sweep the probe length with `EXHALE_JV_PROBE_ARC`, and
   `EXHALE_JV_COLUMN_SCALE` where the comparison calls for it. Both change the
   production action, so a sweep runs on a frozen state, never inside a solve
   whose result is being judged.
2. Record for every direction: the requested `h`, **the full active-set mask
   and the projection displacement**, the realized displacement, the residual
   difference, an independently measured evaluation uncertainty, and the
   forward and central differences in the same units. A clipped direction
   gives the derivative of a projected map; a plateau in such data does not
   certify the unconstrained Jacobian.
3. Record the bound treatment **at each endpoint separately**. If one
   endpoint is projected and the other is only step-shortened, the difference
   is not a central derivative and must not be labeled one.
4. Record whether the reconstruction mode, the WENO smoothness weights, the
   contact-mode dissipation, the positivity repairs and the well-balanced data
   were frozen or recomputed, and state which object is being measured: the
   production action, a frozen model, or the nonlinear trial operator. These
   flags belong to the effective configuration record of section 3, not to
   prose.
5. Taylor remainder:
   `E(alpha) = || Dr^-1 [F(Y + alpha s) - F(Y) - alpha J_ref s] ||`,
   measured on the hydrodynamic, carrier and element blocks separately. A
   quadratic regime before the uncertainty floor is the evidence that the
   reference action is right.
6. Measure additivity AND homogeneity and compare their defects with the
   linear reduction being asked for. A nonzero defect at finite step length is
   expected and proves nothing by itself.
7. A missing plateau has several causes: a crossed bound or branch, a badly
   scaled direction, different closures at the endpoints, too narrow a sweep.
   Say which were excluded.

## 7. Stage C, the linear model on the route P2 uses

**Available unchanged**: `EXHALE_LINEAR_ROWS` (`steady_newton.f90:17424-17446`).

**Not available without changing the route**: the Ritz values, the band
difference, the Krylov size scan and the term-by-term binding row. They sit
inside `trust_region_step`, are gated by `elem_diag_here`, and the route is
chosen at `:16661`; reaching them on the three-unknown route needs
`EXHALE_TRUST_REGION=1`, which replaces the line search by the scaled trust
region and moves the merit onto the model row scaling (`:7734`). They are a
numerical variant with their own control, not an observation.

**Three residual quantities, never conflated:**

```
r_model = -F - J_action(s) - shift(s)     what EXHALE_LINEAR_ROWS prints
r_trial = F(Y + s)                        the prediction test
r_state = F(Y_adopted)                    the accepted state
```

A small `r_model` with a large `r_trial` classifies nothing by itself.

**Record the base state of the scalings, and the arrays.** `Drow` and the
active bounds are formed from the latest residual evaluation, so every Stage C
number carries the state at which they were formed and a check that it is the
same base state as the action. A textual state identity is not enough: a
diagnostic evaluation of another state can overwrite the arrays. Record a
deterministic summary of the arrays themselves, their hash or their minimum,
maximum, norm and worst-cell indices.

Order of inference: verify the action (Stage B), then the residual of the
returned direction against that same frozen action with the shift reported
separately, then the model prediction against the nonlinear change over
smaller feasible steps, and only then classify.

### 7.2 Stage D, the ledger

Stage D is a recording protocol, not an interpretation. For every outer
composition pass and every inner Newton iteration, named separately, record:

- the state identity and the active unknowns;
- the unscaled row measures AND the tolerance-normalized distances, with the
  cell of each;
- the actual scaled state displacement, the step length or trust radius, the

## 8. Closure bias

### 8.1 The control variable, corrected

`eval_residual` either runs the eliminated chemistry and radiation update to a
convergence test or for a prescribed number of sweeps
(`steady_newton.f90:4175-4183`), and the Newton loop forms its Jacobian base
point with `n_eq_sweeps_fixed = n_eq_sweeps_model` (`:17038`). Rev1 said that
count is one. It is one only at the start: `:10653` and `:16723` assign
`n_eq_sweeps_model = n_eq_sweeps_last`, and `:10752` and `:17667` raise it
with `max`. The map is fixed WITHIN one Jacobian evaluation and varies along
the run.

Therefore the experiment must control and record the count, not assume it. For
every base and perturbed evaluation record: the requested fixed count, the
count actually completed, the convergence criterion and whether it was
reached, the seed composition identity, the number of chemical roots that did
not converge, and the closure increment with its temperature and heating or
cooling change.

Record also whether the fixed count was HONORED. An evaluation can exit early
on an inadmissible composition, a missing chemical root or a discarded state,
so a refusal flag and its reason belong beside the counts, together with a
statement of whether `F` is admissible for derivative use at all.

`EXHALE_RESID_SC_MAX` is a cap and does not force an exact count, so it is not
the control. Use the existing `n_eq_sweeps_fixed` interface from a dedicated
diagnostic path, or add an explicit documented override that is off by default
and cannot alter the production route.

### 8.2 The comparison

Two-dimensional: probe length `h` against fixed closure count `k`. For each
`k`, identical seeds and identical endpoint evaluation order, with the same
`k` at both endpoints of every difference; then compare the actions across
`k`. A stable plateau at one `k` does not show that the converged closure
derivative is right, and a change with `k` does not prove a finite-difference
defect. Report `|| Dr^-1 (F - F_jac) ||` and its row distribution at the
actual iterate, naming the route and sweep policy of each side.

One rule: a closure count at which the inner map leaves chemical roots
unresolved, or changes branch, is not a Jacobian validation point. Such a
point may be interesting in itself, but its finite difference is not the
derivative of the intended smooth map.

## 9. M1, the molecular models whose chemistry rows refuse

### 9.1 What the default route does

INSPECTED, `EXHALE_main.f90`, the outer pass loop from `:7005`:
`relax_element_composition` at `:7368-7373` under `he_diffusion`, at the face
mass flux of the current state; `relax_photochemical_composition` at
`:7430-7438` under `transported_rows_exist() .and. .not. block_now`, which is
the default; refreshes at `:7408-7412` and `:7445-7449`; joint certification at
`:7140-7168`; and `:6977-6980` makes the pass cap larger than one exactly when
one of those relaxations is active.

So the route is a block Gauss-Seidel alternation. The refusing carrier or
elemental row is one component of that block iteration, and its value reflects
both the fixed-wind relaxation and the hydrodynamic refresh that follows,
which moves the density, velocity, pressure, temperature, rates and face
fluxes the next composition residual is formed from. It is the residual of the
coupled map, not of the most recent relaxation alone.
`norm(R) = 1.4e-08` means the hydrodynamic subsystem is within tolerance at
the inspected state; the carrier or elemental row above tolerance means the
ALTERNATION has not reached a joint fixed point.
The two `HeH0.083` cases are "hydrodynamically within tolerance at the
inspected state", not "solved".

### 9.2 The alternation audit

Per outer pass, record: the composition displacement ADOPTED and the
displacement REQUESTED before the movement bound; the inner residual and the
ending token of each relaxation; the joint residual after the refresh; and,
added by review1, **compact norms of the full state vector**, `Y(k+1) - Y(k)`
and `Y(k+1) - Y(k-1)`, with the composition displacement.

**On the "map defect".** For the implemented deterministic update
`Y_next = G(Y)`, the quantity `G(Y) - Y` IS the accepted displacement, and
giving it a second name creates no second diagnostic. The two differ only if
the `G` being evaluated omits a constraint, a damping, a rejection or part of
the implemented update, and then that `G` is a different map and has to be
defined: its inner stopping rule, its sweep policy, its admissibility checks
and exactly which constraint was removed. INSPECTED, the carrier relaxation
rejects a trial, restores the thermochemical state and reduces its growth
factor before it can end on the movement bound
(`diffusive_photochemistry.f90:8006-8053`), so a rejected trial is not an
application of the alternating map either. If such a map is evaluated, run it
from a restored snapshot and report an undefined or inadmissible result when
it cannot be evaluated.

Record instead: the carrier change REQUESTED, the change ACCEPTED, and the
reason for every reduction or rejection; the full accepted outer-state
displacement and the difference spanning two passes, under fixed documented
block scales; and the refreshed joint residual, which is the acceptance
criterion. Neither a small displacement nor a small map defect replaces it:
near a fixed point `G(Y) - Y` is approximately `(DG - I)(Y - Y*)`, so a
direction whose eigenvalue of `DG` is close to one can show a small defect at
a large state error. A moving worst cell
makes a maximum look flat while the state moves, and a flat maximum can hide a
two-cycle. A flat scalar is not evidence of a non-joint fixed point: an inexact
inner solve, a movement bound, rejected updates and a cycle all produce it.

### 9.3 The outer cells

Cells 499 and 500 of 500 are r = 27.6 and 28.1. The carrier's outer closure is
explicit: the face rule continues the last physical value into the ghost faces
(`diffusive_photochemistry.f90:4167-4169`) and `carrier_outflow_ghost` does the

`EXHALE_CARRIER_ROW_TERMS=1` writes, per cell and per solved carrier, the

**What those face entries are.** INSPECTED,
`diffusive_photochemistry.f90:5754-5756` and `:5860-5865`: with
`Kj = 1/(cv(j) R0cb)`, `sL = fa(j-1) R0sq` and `sR = fa(j) R0sq`, the file
holds `-Kj sL J(j-1)` and `Kj sR J(j)`. The area and the cell volume are
ALREADY applied, so the four entries sum to the divergence above them. The

### 13.3 Precision, and two checks that must not be confused

INSPECTED: the carrier writer prints `ES14.7` (eight significant decimal
digits) at `diffusive_photochemistry.f90:2829`, `:2835` and `:2841`, and the
loaded-state hydrodynamic profile prints `ES16.8` (nine) at
`EXHALE_main.f90:1305`. A budget reconstructed from such files subtracts large
terms, and a residual far below the discarded digits cannot be recovered from
them: a defect seen in that reconstruction can come from the serialization
alone, even where the arithmetic in memory is consistent.

Any export written for an audit therefore carries at least 17 significant
decimal digits for a binary64 value, for example `ES25.16E3`, or a lossless
binary form with a documented schema, and the geometry is written at the same
precision. Where an EXISTING file is used instead, propagate its rounding
uncertainty and label any cancellation below that uncertainty as unresolved,
not as a defect.

Two checks, reported separately:

1. **Assembly consistency.** Reconstruct the residual independently from the
   exported terms and compare it with the production residual. Its tolerance
   comes from arithmetic and serialization uncertainty.
2. **Stationarity.** Ask whether that reconstructed residual meets the
   physical acceptance criterion. Its tolerance is the certification's.

A checkpoint that is not stationary can pass the first and fail the second,
and agreement between a writer and its reader says nothing about whether the
flux or the source formula is physically right.

### 13.4 Where gravity actually enters, and what the consumer must not omit

This is the part of the contract that decides whether the audit produces a
number or an artifact.

Two different statements, kept apart. **In the momentum row**, INSPECTED
`Source.f90:44-52`, the well-balanced option returns `S = 0` because the
equilibrium pressure and the weight cancel cell by cell, which is what the
header describes when it says that returning zero "is not the absence of
gravity: it is gravity carried in the flux difference in a form that vanishes
on the discrete equilibrium". **In the energy row**, the reason is different
and is established by the assembly itself: `S(3) = 0` in every branch, and the
gravitational work is the `dF3p` term below.

INSPECTED, `RK_rhs.f90:273-275`, the energy row is assembled as

```
dF3p    = dAp*Fp(1)*(Gphi_i(j) - Gphi_c(j))
        - dAm*Fm(1)*(Gphi_i(j-1) - Gphi_c(j))
dF(3,j) = (dAp*Fp(3) - dAm*Fm(3) + dF3p)/dV
```

so the gravitational work rides on the MASS face flux inside the energy flux
difference. A consumer that reconstructs the energy row from `face_flux(3,:)`,
`S(3,:)`, the heating, the cooling and `Sene` alone omits `dF3p/V` entirely.
That omission would be a defect of the audit, not of the production energy
equation.

**The export contract for energy.** Export the numerical mass and energy face
fluxes, the exact face geometry and the cell volume, `Gphi_i` and `Gphi_c`;
export `dF3p/V` as a separately named gravitational energy contribution, or
reconstruct it in the independent consumer from those quantities; state that
it enters with a positive sign INSIDE `dF_E`, so no second gravitational work
term is subtracted anywhere; and export the radiative and chemical heating and
cooling and the transport contributions in the existing convention of
section 11.3.

**An identity the consumer can test.** DERIVED by expanding `dF3p`, with the
mass source zero and a static prescribed potential, writing
`R_mass = (A_R F_mass,R - A_L F_mass,L)/V` and `Q = heat - cool + Sene`:

```
R_energy + phi_cell * R_mass
   = [ A_R (F_energy,R + phi_R F_mass,R)
     - A_L (F_energy,L + phi_L F_mass,L) ] / V  -  Q
```

so that, after volume weighting, the interior faces telescope in the energy
flux augmented by the potential energy transport. The term
`phi_cell * R_mass` must be KEPT at the refusing checkpoints: their mass
balance is not necessarily small, and dropping it would apply a stationary
mass identity while auditing a state that is not stationary.

Use this BESIDE the gas-energy row check and never in place of it: one
combined equation can hide compensating errors in the mass row and the energy
row, and only the two together locate them. Both are assembly-consistency
tests in the sense of section 13.3. They validate the assembly, not the
physics of any source model, and the identity must be re-derived if the
potential ever becomes time dependent.

**The momentum row has four branches, and the ledger differs in each.**
INSPECTED `RK_rhs.f90:231-270`, `Source.f90:44-54` and `steady_residual.f90:277`.
`A` is the face area, `V` the cell volume, `F` the stored numerical momentum
flux, `p` the face pressure and `q` the equilibrium pressure departure.

| reconstruction and balance | `dF_momentum` | explicit `S_momentum` |
|---|---|---|
| PLM, ordinary | `(A_R F_R - A_L F_L)/V` | gravity plus the geometric pressure term of `Source.f90` |
| WENO3, ordinary | `(A_R F_R - A_L F_L)/V + (p_R - p_L)/dr` | gravity from `Source.f90` |
| PLM, well balanced | `[A_R (F_R + q_up,R) - A_L (F_L + q_dn,L)]/V` | zero |
| WENO3, well balanced | `(A_R F_R - A_L F_L)/V + (q_up,R - q_dn,L)/dr` | zero |

Where transport is active every branch additionally subtracts `Smom`. The
export therefore names the branch in force and carries `dr_j`, the face
pressures or the departures that branch uses, the geometry, the explicit
source and the viscous momentum term. Do not add an explicit gravity source to
a well-balanced row a second time, and do not treat the ordinary WENO3
pressure term as though it were already inside the stored momentum flux.

### 13.5 A state inside the reconstruction continuation

INSPECTED, `steady_residual.f90:117-125`: `reconstruction_continuation_rhs`
evaluates PLM and WENO3 separately and returns
`R_lambda = (1 - lambda) R_PLM + lambda R_WENO3`, blending the flux
differences, the sources, the face fluxes and the stored momentum terms
`momentum_ram_divergence`, `momentum_pressure_gradient`, `momentum_gravity`
and the equilibrium pressure force (`:176-178`, `:197-202`), and then restores
the caller's `rec_method`, `use_plm` and `use_weno3` (`:204-208`). It
constructs no blended pair of `face_q_up` and `face_q_dn`.

**What remains available, stated precisely.** The routine returns the blended
`dF` and `S` and leaves the blended momentum diagnostics, so the assembled
momentum row is recoverable as `dF(2,:) - S(2,:)`, less the transport source
where it is active, and the blended terms support attribution provided their
reading respects the balance option. Summing the production row is not an
independent audit of it, and what is genuinely unavailable is the FACE-LEVEL
independent reconstruction: the two branch ledgers are gone.

**Three traps for a consumer, INSPECTED in the same routine.**

1. The blend covers `face_flux` and `face_p` (`:190-191`) and does NOT cover
   `face_q_up` or `face_q_dn`. The WENO3 evaluation runs last, so after a
   blended call those arrays hold the WENO3 departures alone. A reader that
   assumes every stored face array is on the same homotopy mixes two
   conventions without any sign of it.
2. `WL` and `WR` are blended states (`:186-189`) while `face_flux` is the
   blend of the two schemes' fluxes. The numerical flux is not linear in its
   arguments, so a flux recomputed from the blended states is NOT the stored
   face flux. The postprocessor design of section 13.2 must take the stored
   flux, not rebuild one.
3. At a pure endpoint the routine still sets and then RESTORES the caller's
   `rec_method`, `use_plm` and `use_weno3` (`:162-170`, `:207-210`), so the
   flags in force afterwards do not say which branch ran. Derive the effective
   branch from the continuation control, and record it in the effective
   configuration of section 3.

Consequence: for `0 < recon_lambda < 1` the flags left behind do not describe
one pure reconstruction, and the final departure arrays cannot rebuild the
momentum row at face level. Two admissible responses, chosen before such a state is audited:

1. record `lambda` and capture the two branch ledgers BEFORE the blend, then
   verify that their weighted sum is the row that was solved; or
2. state that the first audit supports the pure endpoints only and refuse an
   intermediate `lambda`, reporting it as an unsupported diagnostic
   configuration and never as a failure of the physical equations.

The energy identity of section 13.4 stays algebraically compatible with the
blend at a fixed state and potential, because its flux expression is linear in
the blended mass and energy fluxes. That does not supply the missing momentum
decomposition.

### 13.6 Which assembly produced the row

A third selector stands in front of everything in sections 13.2 to 13.5, and
no earlier revision of this plan named it.

INSPECTED, `steady_residual.f90:239-247`: `assemble_residual` sets
`rows_kind = ROWS_PRODUCTION` and then, WHEN THE STATE KIND IS NOT THE
MARCHING ONE, replaces it by `generic_precision_rows_selected()`, so the row
is assembled by `hydrodynamic_rows_in_quadruple_precision`, by
`hydrodynamic_rows_in_double_precision`, or by
`reconstruction_continuation_rhs`.

INSPECTED, `hydrodynamic_rows.f90:160-182`: the selector reads
`EXHALE_RESID_QUAD` at EVERY call rather than caching it, `1` giving the
quadruple rows and `2` the same generic text at the double kind, anything else
the production routines. Mode `2` exists to be bitwise identical to
production.

Three consequences for this work:

1. **The effective configuration must carry it.** Because it is read at every
   call, two evaluations inside ONE process can use different assemblies. Any
   A and B comparison, and the route equivalence of section 5.1, records the
   value in force at each evaluation, not once per run.
2. **The export names the assembly.** A budget reconstructed from an export
   is a statement about the assembly that produced it. The generic rows store
   the interface fluxes, the face pressures and, under the well-balanced
   option, the departures, but they do NOT fill the momentum term arrays or
   the equilibrium pressure force: `assemble_residual` evaluates those
   separately for the assembled state (`steady_residual.f90:263-266`). An
   export must say which of the two produced each field.
3. **Mode 2 is an instrument this plan can use.** A whole evaluation under
   the generic double rows that is bitwise the production evaluation is an
   existing, strong assembly-consistency check in the sense of section 13.3,
   and it costs one extra evaluation. Use it before building a new consumer.

The generic text refuses two configurations outright, with `error stop`
(INSPECTED, `hydrodynamic_rows.f90:289-300`): a reconstruction continuation
with `0 < lambda < 1`, because a blended flux carries neither scheme's
pressure convention, and the low-Mach contact-mode dissipation. Those
refusals are the correct behavior and they bound where consequence 3 applies.

## 14. Stage F, continuation

Descend in `log(XUV)` from the certified x0.10 in moderate increments,
reducing the increment where a correction fails, with a predictor from the
previous successful states, the base model, composition, grid policy and band
definition fixed, and the spectrum of every point archived. Record the branch
markers, the smallest successful increment, the residual structure and the
reason each correction ended. A suspected turning point calls for an augmented
continuation equation, not a smaller step. Mode C throughout.

The result is "the lowest certified XUV on the tested branch, with this grid,
boundary law and numerical method". It is never a statement that no stationary
atmosphere exists: a fold, an unresolved branch, a discretization artifact and
a numerical failure all produce the same picture, and time dependence can be
established only by an accurately integrated physical time calculation.

## 16. What is still open

- Which questions need Mode C. Phases 2 to 5, 6b and 8 are Mode R, restored
  disposable probes, and phase 1 is a historical audit of the stored records
  together with Mode R evaluations of the current operator; phase 6 is Mode C as soon as it advances a RETAINED trajectory, and a
  historical audit if it only reads existing logs; phases 7, 9 where a
  current-branch state is needed, and 10 are Mode C. Mode C does not mean a
  campaign: a short controlled failed solve with its initial state, budget and
  ending preserved is admissible evidence.
- The four defects of section 10. Two of them, 10.1 and 10.2, are unambiguous;
  10.1 additionally needs the entry snapshot contract and its five tests
  before the option can be used at all, and the coupled block must recompute a
  fresh residual from the entry snapshot and verify it before accepting the
  handover, so that a stale token cannot authorize a state that no longer
  meets the condition that triggered the transition.
- The charge assertion of the conversion, to be added when those checks are
  next touched. It is a missing assertion, not a violation: the transfer moves
  mass only between two neutral species.
- Whether any of the remaining states has a stationary solution. Nothing in
  this plan, in the review or in review1 establishes that either way. The
  strongest defensible conclusion available is whether a given operator and
  route are reproducible and where their balance fails.
