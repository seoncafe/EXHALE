# Inputs of the H2 Lyman-Werner self-shielding table

`src/modules/lower_atmosphere/h2_self_shielding_table.f90` is generated by

```
python3 src/utils/h2_shielding_table_line_by_line.py \
        src/utils/h2_shielding_lbl/abs src/utils/h2_shielding_lbl/cloudy_grid3
```

and this directory holds everything that command reads, moved here on
2026-09-06 from the scratch directory of the 2026-09-03 session (P38,
`md/p38_line_overlap_shielding.md`), where it would have been lost with
`/tmp`. MEASURED 2026-09-06: the command above regenerates the shipped
module byte for byte.

| path | what it is | provenance |
|---|---|---|
| `abs/abs_T####.npz` | `sigma_pump(N)`, `p_single(N)` on the 39-point column axis, one file per temperature of the grid (700 to 3200 K) | `run_abs.py <T>` (this directory), 2026-09-03 |
| `abs/abs_*.log` | the run lines of those nine calls | same |
| `cloudy_grid3/*.rat` | the 27 CLOUDY `save h2 rates` files read for the trapping ratio `p_eff/p_single` only, plus the deck abundance file and the diagnostic patch applied to CLOUDY c25 for them | CLOUDY c25 runs of 2026-09-03 (P38 stage 2) |
| `lbl.py` | line list and level data reader, LTE populations, the overlapping-line shielding curve | written for P38 |
| `lbl_table.py` | `absolute_curves`: `sigma_pump` and `p_single` per unit incident photon fluence of a flat `F_lambda` band | written for P38 |
| `run_abs.py`, `grid_lbl.py` | the drivers that wrote `abs/` and the normalized curves of the memo | written for P38 |
| `p38_lib.py`, `meudon_extract.py` | readers of the Meudon PDR outputs used for the cross-checks of the memo | written for P38 |
| `PDR71/data/Levels`, `PDR71/data/UVdata` | the H2 level energies and the Lyman and Werner line list (Abgrall, Roueff and Drira 2000, A&AS 141, 297) as distributed with the Meudon PDR code version 7.1 (Le Petit et al. 2006, ApJS 164, 506) | third-party data, copied unchanged; `lbl.py` reads them at `PDR71/data` relative to itself |

Nothing else of the Meudon distribution (its source, its outputs) is kept:
the PDR runs of the memo are cross-checks, not inputs of the table.

## The band

`lbl_table.absolute_curves` builds the line list to `wl_max = 1201 A` (its own
default, which it passes to `lbl.build_linelist`; the lines longward of 1110 A
start from vibrationally excited levels and matter at the temperatures of the
grid) and normalizes `sigma_pump` per photon of the flat band
`WL_LO, WL_HI = 912, 1201 A`.  `lbl.py`'s own defaults are left at the 1200 A
of the memo, because `grid_lbl.py` reproduces the memo's curves from them. THE
TWO ARE ONE INTERVAL, which is what makes the table's column integral of
`sigma_pump` a fraction of the band photons: MEASURED over the whole
temperature and density grid, that integral reaches 0.6903 to 0.9974 at the
top of the column axis, and cannot pass 1.

Until 2026-09-06 the line list ran to 1200 A while the normalization band
stopped at 1110 A (Draine & Bertoldi's interval, where interstellar H2 in
v = 0 pumps). LW-NORM measured the consequence: the column integral reached
1.515, the photon content of 912-1200 A over 912-1110 A, so the table rated
45 per cent more line absorptions than the 912-1110 A beam of
`lyman_werner.f90` lost. Item 6 chose between rebuilding on
912-1110 A and widening the beam; the user adopted the widening on
2026-09-06 (item LW-NORM-B), because the
1110-1201 A lines are real absorbers of a 700-3200 K layer and carry about a
third of the dissociations at saturation. `F_BAND_ERG` in `lbl_table.py`
carries the derivation of the deck's flat band flux over the wider interval;
the value cancels out of `sigma_pump` and only the band width and the mean
band photon energy enter.
